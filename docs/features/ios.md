# iPhone and iPad

The iOS app, its players (Apple's and mpv) and what isn't on iOS yet.

Read CLAUDE.md first: its rules (keys, ids, privacy, licences, focus, server load) apply here too.

- `:ios-app` + `iosApp/` – the iPhone/iPad app: `IosPlatform` (DataStore files in Documents, Darwin engines, `appleCapabilities` = `PlayerEngine.APPLE`: MP4/MOV direct play, fragmented-MP4 HLS, subtitles as WebVTT in HLS or burned in; `IosThemeMusic`; `IosNewEpisodeNotifier`: local notifications, checked in a `BGAppRefreshTask` (`AppDelegate` in `NitrateApp.swift`, `MainKt.checkNewEpisodes`) and after library changes, taps open the item via `IosApp.openItem`; Group Watch Session reminders as local notifications on a `UNCalendarNotificationTrigger` 15 minutes before each group's next party (`scheduleParties`, identifiers `party-<group>`, set again whenever the groups load and in the background refresh; iOS gives no time to look again when one fires, so its text is the party as last loaded, and a party that's off or the user can't make sets none; a tap opens the party, `nitrateParty` → `MainKt.openItem("party:…")`); no downloads or self-update yet) and `MainViewController` showing `MobileApp`, built into the static `NitrateKit` framework that the XcodeGen project `iosApp/project.yml` (Swift host `NitrateApp.swift`) links. The iOS player (`mobile-ui` iosMain `ApplePlayerSession`, `Player.ios.kt`) plays in Apple's player, or in mpv when the server would otherwise convert it for Apple's (`resolvePlayback(deviceCaps = Mpv.capabilities(...))`, `PlayerEngine.MPV`: every container, styled/image subtitles as they are; `MpvTracks` maps server stream indices to mpv aid/sid): mpv is MPVKit's LGPL product only (never MPVKit-GPL), driven from Swift (`iosApp/Nitrate/MpvPlayerView.swift`, `NitrateMpvPlayer`: Vulkan over MoltenVK, VideoToolbox) through ios-app `NitrateMpv`/`useMpv` (`close()`, not `release()`, which NSObject has) into mobile-ui `Mpv.factory`, with Nitrate's own controls (`MpvControls`). Both get the shared overlays (`PlayerOverlays.kt`: skip, Up Next, credits banner, `TrackPicker`); tracks via `trackSetup`/`pickTrack` (mpv switches in place for files played as they are). Linking needs macOS: `.github/workflows/ios.yml` builds an unsigned `nitrate-ios-<name>.ipa` for sideloading on pushes to `ios-app`, and the iOS release is its own workflow, `ios-release.yml`: `release.yml`'s `ios-start` starts it once the release exists (passing the release's tag, name, run number, commit and run id), so the Mac build (the Kotlin/Native release link, 30+ minutes) never holds up the next release (releases queue one at a time); it has its own concurrency group that cancels an older iOS build when a newer release starts one. Its `ios-check` (Ubuntu, no Mac waited for) builds only when something the app is built from changed since the last release with an .ipa (shared Kotlin other than Android/desktop-only code, ios-app, iosApp, the build setup, ios-release.yml); otherwise `ios-publish` adds that .ipa under this release's name (saying so in the notes). `ios-publish` adds the .ipa when it's there and writes SHA256SUMS again once the release run has finished (the release's own `checksums` job writes it first). Kotlin/Native's `~/.konan` is cached between runs. The iOS player also has More (`IosPlayerMore`: speed in Apple's player, second subtitles via `ApplePlayerSession.setSecondSubtitle` drawn at the top, how it plays from `infoRows`, Media info), group chat (the Chat button with its dot, `PlayerChatSheet`/`ChatPanelSheet`, `NoteToasts`: the watch group's conversation on the title popping up as it's reached, live in a Group Watch Session too; Turn off for one playback), the session's countdown and notices (`SessionOverlay`, as on Android), "Still watching?" (input = taps on Nitrate's buttons plus pauses/jumps seen by `ApplePlayerSession.onInput`, since Apple's controls take the touches) and episodes rolling on at the end. Downloads: `IosDownloadScheduler` runs `DownloadManager.runQueue` in the app (with a background task's extra minutes; retried while offline; `resume` on opening); `ApplePlayerSession.loadLocal` plays a download from the device (MP4/MOV in Apple's player, other containers in mpv), saving watch state with `recordPlayback`; Wi-Fi only applies on Android. Licence texts are bundled from `core-android/src/main/assets/licenses` by `iosApp/project.yml`. Music and audiobooks play in `IosListening` (ios-app; core `music/ListenQueue` keeps the queue in playing order, which Android leaves to ExoPlayer): an `AVQueuePlayer` with the next song loaded behind the one on, the Authorization header on each `AVURLAsset` (`AVURLAssetHTTPHeaderFieldsKey`), as it is else converted (a failure as it is plays converted from the same spot, one converted is skipped), levelling as volume, reports as Android's, books' speed/±15/30 s/chapters/sleep/resume, downloads from the device; the lock screen and Control Center through mobile-ui `platform/NowPlaying` (`MPNowPlayingInfoCenter`/`MPRemoteCommandCenter`, the AVAudioSession playback category; one owner at a time), also used by `RemoteFollowing` for another device's playback (app-core `remote/RemoteFollower`, the looking shared with Android's `RemoteControlService`; iOS shows it only once Nitrate has played sound this run). Cast and Readium have their Kotlin bridges (`useCast` → mobile-ui `IosCast` for `rememberCast()`, `useBookReader` → `IosPlatform.epubReader()`) but their Swift sides are drafts in `iosApp/Drafts/` (not built; switching on needs a Mac, see its README), so for now no Chromecasts are listed and EPUBs use `EpubScreen`. Not on iOS yet: the transfer page (its server is JVM-only), speed in mpv, Android's sound and timing choices.
