# Nitrate Companion (server plugin)

What the plugin does and how the apps use it.

Read CLAUDE.md first: its rules (keys, ids, privacy, licences, focus, server load) apply here too.

- `companion/` – Nitrate Companion, a Jellyfin server plugin (C#, .NET 10, against Jellyfin 12.4's NuGet packages; GPL-3.0 because it builds on Jellyfin's libraries) for what Jellyfin has no API for: chat in SyncPlay groups (`/Nitrate/Chat`, long polling), single sign-on (`/Nitrate/Sso`, open), household channels (`/Nitrate/Channels`), watch partners and private accounts (`/Nitrate/Partners`, `/Nitrate/Privacy`; a group's schedule carries `Together` ("How we watch": together only, false by default and for schedules stored before it) and the group view `TogetherFromId`, the first part nobody in the group has seen, for the apps' guard) and shared screenplays (`/Nitrate/Scripts`: owner + invited members, compare-and-set edits on the latest version, long-polled edits and cursors, kept in the plugin's database: `Scripts/DbScriptStorage`, every accepted edit one `script_edits` row, the whole script (`scripts` row) written at most every 30 s while people type and at once otherwise, the edits after the last whole copy replayed on start; the older `scripts/` folder moved in once), TV and receiver check clips (`/Nitrate/TestClips`, embedded from `TestClips/`), household device summaries (`/Nitrate/Devices`, admins read), watch-together invites (`/Nitrate/Together/Invites`, `Together/InviteHub`, in memory for 3 hours), scenes in the credits (`/Nitrate/Credits/{itemId}`, `Credits/CreditFinder` = the apps' thumbnail reading in C#, keep in step; `CreditScanner` = the nightly "Find scenes in the credits" task: every film and episodes tagged with a stinger, the last 30% decoded keyframes-only by the server's ffmpeg into 48×27 grey grids with their `showinfo` times, held onto a 5 s grid; results per file version in the plugin's database (`Storage/CompanionDb`, see below), with `CreditFinder.FinalCredits`: the last stretch of credits running to the end, after any scene, across breaks shorter than a scene, stored as `OutroStartMs`/`OutroEndMs`; `CreditResult.Format` makes older results be read again), intros (`Intros/IntroScanner` = the nightly "Find intros" task: the opening 30% (3–10 min) of each episode's sound read once by the server's ffmpeg as 8 kHz mono into an `AudioPrint` (32-bit band-energy-change frames every 64 ms, kept per file version in the plugin's database), each season's episodes compared with their neighbours by `IntroFinder` (the longest shared stretch of 15–150 s, edges trimmed to where matches are dense; results in the plugin's database), plus "Previously on…" recaps by `RecapFinder`: the opening before the intro (else its first 4 min) matched clip by clip (`AudioPrint.SharedRuns`, ≥ 2 s each, gaps ≤ 8 s, matches inside an earlier episode's intro ignored) against the whole sound of the 3 episodes before it in the show (whole-sound prints kept only for each show's last 3 episodes, `IntroStore.KeepWholeOnly`, so a new episode never has its predecessors read again; a recap is only looked for in a new or changed episode, the others keep theirs), starting within 30 s, ≥ 15 s long, at least half clips; `Segments/CompanionSegmentProvider` (an `IMediaSegmentProvider`, "Nitrate Companion", switchable per library; `RunSegmentPluginProviders` after a find) hands Jellyfin each episode's Recap and Intro and each title's final credits as an Outro, so Skip Intro/Recap/Credits and Up Next work in every app with no app change, and an Outro never holds a mid- or post-credits scene (core `CreditScenes` takes the earlier of an Outro and the server's credits start, and an Outro running to the end is no scene marker); seasons are looked at again only when an episode is new or changed), smart collections (`SmartCollections/SmartRule` in the plugin configuration, edited on its dashboard page: all set conditions must hold, lists match any entry; `SmartCollectionUpdater`, "Update smart collections", nightly and via `SmartCollectionWatcher` ten minutes after films/shows/episodes are added or removed, keeps one real Jellyfin collection per rule through `ICollectionManager`, remembered in the plugin's database (`companion.db`, `pairs` kind `smart-collections`; the older `smart-collections.json` moved in once) and made again if deleted; a removed rule leaves an ordinary collection), files' timing (`Timing/TimingScanner`, the nightly "Check files' timing" task: the server's ffprobe reads each film's and episode's streams' start times and the packets of its first 5 minutes, no decoding; `TimingFinder` names a sound/picture start offset ≥ 100 ms, gaps in the sound ≥ 300 ms or picture ≥ 500 ms, timestamps going backwards and a variable frame rate; per file version in the plugin's database; `GET /Nitrate/Timing` lists titles with issues, admins only; feature `timing`), spoken-line search (`/Nitrate/Lines`, `Lines/LineIndex`: SQLite FTS5 in `lines.db`, using the server's own Microsoft.Data.Sqlite, never shipped; filled by the "Index spoken lines" scheduled task, nightly and incremental, via `ISubtitleEncoder` as SRT) and comics page by page (`/Nitrate/Comics/{itemId}` listing format, pages with sizes from `Comics/ImageHeader` and ComicInfo.xml, `/Pages/{n}`; `Comics/ComicStore`: CBZ read in place, CBR/CB7/CBT unpacked once with SharpCompress (MIT, shipped beside the plugin: `tools/companion-manifest.py` `ASSEMBLIES`) into the server's cache folder, the most recently used within 4 GB; PDF and EPUB only named, the apps take the whole file; `EnableComics`; `ComicPages` keeps in step with core's) comic catalogs (`/Nitrate/Catalogs`: OPDS/CLU catalogs the admin sets up on the dashboard page, fetched with their sign-in only on their own server, books served page by page, each person's place kept; see Comics below) request timing for the apps' query analyzer (`/Nitrate/QueryTimes`, feature `querytimes`; `/Household` for admins: every person's tagged requests by shape = method, path with `{id}`, parameter names never values, `QueryTimeStore.ShapeOf`/`Household`), lighter Home (`Api/HomeController`, all from the server's database, never media files: `/Nitrate/Home` = Continue Watching, Next Up, "Latest in…" for film/show libraries and Because you watched in one answer of Jellyfin's own `BaseItemDto`s, feature `home`; `/Nitrate/Because` from `Recommendations/BecauseBuilder`, the nightly "Make Because you watched" task (2:00; `BecauseRows` = the apps' rules; rows kept in memory only, `BecauseStore`, a few dozen ids per person; after a start `BecauseWarmup` makes them again in the background, 3 minutes in, for everyone who watched something in the last 30 days, one at a time; asked before theirs is ready, a person gets none that once and theirs is made then, never a wait (`For`/`BuildSoon`); over 30 h old they're remade in the background; watched titles left out when read), feature `because`; the app never keeps an empty answer from it; `/Nitrate/Formats` from `Formats/FormatIndex`, each title's codecs/bit depth/range/DV profile/sound kept in memory and forgotten on `ItemAdded/Updated/Removed`, shows from their episodes, feature `formats`) and the watch diary (`/Nitrate/Diary`, `Diary/DiaryHub`, one database row per watch, `Storage/DbDiaryStorage` writing only what changed, the older `diary/` folder moved in once; `DiaryRecorder` hosted service records `PlaybackFinished` saves that ended played with no resume point). Every file-reading nightly task (Find intros 1:30, Index spoken lines 3:00, Find scenes in the credits 4:00, Check files' timing 4:30) keeps its results per file version and reads a file again only when it changes; one runs at a time (`Scanning/FileReading.Gate`), and a file that couldn't be read waits a day, then a week, then a month before another try, or until it changes (`Scanning/ReadFailures`). These results, the intro task's fingerprints and the read failures live in one SQLite database, `companion.db` in the server's data folder (`Storage/CompanionDb`, the server's own Microsoft.Data.Sqlite, WAL; tables `results` (kind, item, json), `prints` (item, whole, version, blob), `failures` (task, key, json), `pairs` (kind, key, value): smart collections' rule → collection, and the watch partners' state as one row, `DbPartnerStorage`, the older `partners.json` moved in once; `records` (kind, owner, key, json, at): diary entries, catalog places and household device reports, `Storage/DbDeviceReportStorage` one row per person and device, the older `devices.json` moved in once; `scripts`/`script_edits` for screenplays), one row written per title, never a whole file rewritten; the older `credits.json`, `timing.json`, `intros.json` and `intro-prints/` are moved in once on start and deleted (`ImportResults`/`ImportPrints`). Because you watched (2:00) and smart collections (5:00) use the database only. Insights in the same database (`Insights/`, `Api/InsightsController`; `records` kinds below): request timing trends (`QueryTrendRecorder` hourly folds `QueryTimeStore` into one `query-day` row per day and shape, a log2 histogram, 90 days; `GET /Nitrate/QueryTimes/Trends`, admins), wrong-segment votes (`POST /Nitrate/Segments/Feedback`, `segment-vote`: an admin's vote or two people's marks the title's intro/recap/final credits rejected (`IntroRejected`/`RecapRejected`/`OutroRejected`, read through `Effective()`, kept across rescans of the same file version) and re-runs the segment providers; feature `segmentfeedback`), real watch time (`SittingRecorder` from the server's playback events, any app: one `sitting` row per sitting of a minute or more, pauses not counted, `GET /Nitrate/Watching`; feature `watching`), playback trouble (`POST /Nitrate/Problems` failed/converted per device, `problem`, 90 days; `GET` admins, by title; feature `problems`), moments (`/Nitrate/Moments`, `moment`, 500 per person, optionally shared with one of the person's watch groups, whose members see it; feature `moments`) and watch-together chat history (each chat message sent is also kept as a `chat` row under what the group was playing with the group's members at the time, 3 years, `KeepChatHistory` on the dashboard page (on by default); `GET /Nitrate/Chat/History?itemId` returns only messages the caller was there for; feature `chathistory`). Apps find it with `GET /Nitrate/Companion` and hide features without it. Released as `nitrate-companion-<v>.zip` plus a plugin-repository manifest on the `companion-repo` release (`tools/companion-manifest.py`). Updates itself: `Updates/SelfUpdater` asks the server's plugin repositories every 6 hours (first 10 minutes after start) and installs a newer version of itself through `IInstallationManager` unless auto-update is off on its plugin page; with `RestartForUpdates` (off by default, dashboard "Finish updates by restarting at night") it restarts the server (`ISystemManager.Restart`) once a newer copy waits for a restart, in the two hours from `RestartHour` (server time, default 4) and only with nothing playing (`UpdatePolicy`). The csproj sets only `<Version>`, so the release's `-p:Version=0.1.0.<run>` stamps the DLL too: Jellyfin compares the running DLL's version with meta.json and the repository's, so never pin `AssemblyVersion`. Its plugin id is a storage key: never change it. Test with `dotnet test companion/Nitrate.Companion.Tests`.
- Search what people say (Companion feature `lines`): `MediaServer.searchLines` → core `lines/SpokenLine` (title, `where` = S/E or year, never an episode name; the lines either side); both apps' search adds "Said in…" (first when `SpokenLines.looksLikeQuote`), which plays from `SpokenLines.startAt` (3 s early) through the guarded play path (phone `AppActions.playFrom`, TV `PlaybackGate.play(startMs =)`). The server only returns titles the caller can see.
- Watch diary (Companion feature `diary`): every film/episode finished in any app, with date, rating (1–10 = half stars) and note; core `diary/Diary` (`stars`, `rewatches`, `letterboxdCsv`, `asHistory` so "Your year" counts every watch on its date, Jellyfin's last-played record before the diary began); `MediaServer.diary`/`logWatch`/`editDiary`/`deleteDiary`; downloads finished offline are logged on sync. Phone `DiaryScreen` (edit, remove, Letterboxd export) and TV `settings/DiaryScreen`, from Settings when the server has it.
- Single sign-on (Companion feature `sso`; settings on the plugin's dashboard page): the plugin's `Sso/SsoService` runs OpenID Connect (code + PKCE; id token checked against the provider's JWKS with the framework's crypto, no extra libraries) and issues a Jellyfin token through `IDeviceManager.CreateDevice` for existing users only (user name claim, verified email = user name, admin links; optional group). Devices `startSso` → show `SsoRequest.url`/`code` (TV: `QrCode`, ZXing) or open it in the browser (phone) → `pollSso` until `Done`, which signs in like a password would. The browser page asks to confirm the device's code before going to the provider.
- Channels (pseudo-TV; Companion feature `channels` + core `channels/ChannelsPlugin`, on by default): admins make `HouseChannel`s (lineup `ChannelSource`s, `ChannelMix`, `alignMinutes`, `ChannelBlock` time slots, `everyone`/`users` grants). The plugin makes and stores the schedule a few days ahead (`Channels/ChannelScheduler`: per-source cursors, undone by `DropFuture` on edits so shows keep their place), so the guide is the same for everyone; nothing ever streams by itself. Tuning in (`MediaServer.tuneChannel`) gives what's on now and what follows; apps play it as a queue from the start of each (`playQueue`), never mid-program. core-android `ChannelsViewModel`; TV `ui/channels` (menu stop `MenuStops.CHANNELS`, guide grid via `Channels.asTvPrograms` + `Guide.cells`, held OK, "Edit a channel" or a programme's "Edit this channel" edits), phone `Channels.kt` (Library tab entry). Calls in `core/jellyfin/JellyfinChannels.kt`, outside the OpenAPI contract test.
- Companion insights in the apps: players feed `AppContainer.skipWatch` (core `companion/SkipWatch`: a Skip pressed and a jump back into the skipped part within 20 s reports it wrong; "Watch credits" is a choice, never counted) — the phone/iOS Skip buttons and the TV's (`ui/player/SkipSegmentButton`: "Skip intro"/"Skip recap" bottom right while one plays, 10 s by itself on entering it (taking focus only when nothing else has it, so one OK skips) and again whenever the controls are up; not in recap clips or test plays; Back puts it away); `PlaybackSession` reports a conversion or a failed direct play once per title per run (`reportProblem`); "Mark this moment" in player More (TV Settings tab, phone `MarkMomentRow`); details pages have "Moments" (play from one, remove your own) and "Earlier chat" buttons (`MomentsAndChatButtons` in each app): chat history is never shown unless asked for; "Your year" adds real watch time (core `WatchTime.forYear`/`line`); the query analyzer adds "Over time" (`AppContainer.queryTrends`) and Household devices "Titles with trouble" (`problemTitles`), both admins only. All hidden without their feature.
