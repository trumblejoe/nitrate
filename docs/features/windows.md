# Windows (desktop)

The desktop app (Windows first; Linux and macOS run it too): the shared phone/tablet screens in a window, its player and packaging.

Read CLAUDE.md first: its rules (keys, ids, privacy, licences, focus, server load) apply here too.

- `:desktop` (Compose for Desktop, JVM 21) shows `MobileApp` from `:mobile-ui` in a resizable window (`Main.kt`, `DesktopContent`): from 840 dp wide the tablet layout (two-pane details and Settings) takes over by itself. `:app-core` and `:mobile-ui` have a `jvm("desktop")` target; `desktopMain` holds the actuals: `Platform.desktop.kt` (java.text dates/numbers; `PlatformActions` = browser via `java.awt.Desktop`, AWT clipboard, toasts as the window's snackbar (`DesktopToasts`), volume to the player (`DesktopVolume`); `PlatformBackHandler` is Compose's own `BackHandler`, so Esc goes back (Compose desktop maps Esc to back navigation; the mouse's back button is turned into Esc by the window); notification permission is a no-op; pictures and files through AWT's `FileDialog` (`DesktopWindow.frame`); no speakers question (`rememberSoundOutput` null); licence texts from the classpath (`licenses/`, `core-android/src/main/assets` added as resources); the transfer page is core's JVM `TransferServer` on the PC's LAN address; no Cast, no remote following), `Epub.desktop.kt` (EPUBs read as text, chapter by chapter: no web view on the desktop) and `Player.desktop.kt`.
- `DesktopPlatform` (`AppPlatform`, appKind `desktop`, `DeviceKind.TABLET`): DataStore files and small `FileKeyValues` property files in `DesktopFolders.system()` — Windows `%APPDATA%\Nitrate` (cache `%LOCALAPPDATA%\Nitrate\cache`), macOS `~/Library/Application Support/Nitrate`, Linux `$XDG_DATA_HOME/nitrate`; downloads in the user's Videos (Movies) folder under Nitrate; `NITRATE_HOME` puts everything in one folder (tests, trying things). OkHttp (16 requests per server). The device id is kept in `device.properties`; the device name is the computer's. Downloads run in the app (`DesktopDownloadScheduler`: `runQueue` with retries while offline, smart downloads every 4 hours, `resume` on opening). No theme music or new-episode notifications yet (`ThemeMusic.None`, `NewEpisodeNotifier.None`).
- Profile: core `playback/DesktopPlayback.capabilities` (`PlayerEngine.MPV`): every codec in `VIDEO_CODECS` direct plays up to 8K, all marked hardware (a PC decodes them on the GPU or has the CPU for it, and mpv deinterlaces), 10-bit except MPEG-2/MPEG-4 Part 2/VC-1, every audio codec decoded by mpv, every HDR kind allowed whatever the screen (mpv tone-maps for SDR screens), Dolby Vision 5/8 (profile 7 as its base layer), styled and image subtitles as they are. Bitstreaming (`audio-spdif`) is per codec in the player's settings, off by default (`DesktopPlayback.spdifOption`).
- Updates (`DesktopUpdater`): GitHub releases on the build's channel (`version.properties` generated from `NITRATE_VERSION_NAME`/`NITRATE_VERSION_CODE`/`NITRATE_DESKTOP_CHANNEL`; local builds never update), asset `nitrate-desktop-<name>.msi` (`Releases.parse(…, "desktop", ".msi")`), checked against SHA256SUMS, then `msiexec /i` and the app closes; a portable copy (marker `portable.txt` in the ZIP) opens the release page instead.
- Keys: F11 full screen (Esc leaves it first), Esc back; the player adds its own (below).
- Player (mobile-ui desktopMain `Player.desktop.kt`, `DesktopPlayerSession`, `DesktopPlayerMore`): libmpv behind `MpvPlayer` (`Mpv.desktop.kt`; `DesktopMpv.factory` is set by `:desktop` when libmpv loads, else the player says what's missing, `DesktopMpv.missing`). The session plays the file as it is (the desktop profile), sends the account's Authorization header to mpv for the stream and subtitle files (`change-list http-header-fields append`, one entry, commas and all; never `api_key`), maps the server's picks to mpv's ids with core `MpvTracks` (subtitle files `sub-add`ed after the file opens), switches tracks inside mpv without restarting (remembered per show as everywhere, `trackSetup`/`pickTrack`), reports start/progress every 10 s/stop (track changes report at once), keeps a download's watch state on the PC, and if mpv can't play the file (end-file error) asks the server once to convert it from the same spot (`forceTranscode`). Controls: Nitrate's own (shown on mouse movement, hidden after 3 s while playing, the pointer hidden with them): Back, title, group button, Audio, Subtitles, Chapters (not in easy mode), Info (the plan's rows plus what mpv says: decoder, hardware decoding, picture, colour, dropped frames, sound out, buffered), More (speed, sleep timer, second subtitles, audio sync and subtitle timing for this playback, and "This PC": bitstreaming per codec, the picture's output, hardware decoding, `DesktopPlayerSettings` in `player.properties`, device-only, never synced), the timeline with scrub thumbnails on hover and drag (`TrickplayPreview`), play/pause, ±10 s, volume (0–130, kept), full screen. Keys: Space/K play-pause, ←/→ (J/L) 10 s and with Shift 30 s, ↑/↓ volume, M mute, F full screen, media keys; a click plays/pauses, a double-click goes full screen; Esc closes what's open, then leaves full screen, then the player. Shared overlays as on the phone: skip intro/recap, Up Next (episodes roll on, next film offered), scenes in the credits, "Still watching?", group chat notes and sheet, group button and counting banner, second subtitle line; the remote's commands (`RemotePlayer`) and volume (`DesktopVolume`).
- mpv binding (`:desktop` `mpv/`): `MpvApi` (what Nitrate uses of client.h/render.h, without pointers) with `JnaMpvApi` over JNA (Nitrate's own declarations from mpv's public headers; `LibMpvLoader` finds `libmpv-2.dll` in Compose's resources folder or `NITRATE_MPV_DIR`, else the system's libmpv on Linux/macOS for development; client API 2.x). `LibMpvPlayer` (`MpvPlayer` over `MpvApi`): options (no config/scripts/OSC/key bindings, `input-cursor=no` so the mouse is Nitrate's, `keep-open` so the end holds for Up Next, cache, `ao=wasapi` on Windows, `audio-spdif` from the bitstream choice with `audio-exclusive` for TrueHD/DTS-HD), observed `time-pos`/`duration`/`pause`/`eof-reached`/`paused-for-cache` on an event thread, and the picture two ways (`VideoOutput`): WINDOW (Windows' default) embeds mpv's own window (`wid` = the heavyweight AWT canvas's handle in a `SwingPanel`, started once the canvas is displayable and destroyed before it goes) with `vo=gpu-next`, `gpu-api=d3d11`, `hwdec=auto-safe` and `target-colorspace-hint` (HDR goes out as HDR when Windows' HDR is on; SDR screens get libplacebo's tone mapping); SOFTWARE (elsewhere, or chosen) uses the render API's "sw" backend into triple-buffered Skia bitmaps (RGB0 into `RGB_888X`, rendered straight into the bitmap's memory) that Compose draws (`hwdec=auto-copy-safe`; CPU-heavier at 4K, SDR out). Trade-off: Compose can't draw over a native window inside its own, so with WINDOW the controls go in a `Popup` and `main()` sets `compose.layers.type=WINDOW` (at start, from the saved choice) so popups and dialogs are windows of their own above mpv's; the overlay is filled with a 0.4% black so clicks reach it instead of passing through to mpv. A change of output applies to the next video (the layers setting to the next start).
- Tests: `LibMpvPlayerTest` (a fake `MpvApi`: options, the header as one entry, tracks, sub-add after loading, events into state, seconds with a dot in any language), `DesktopPlayerTest` (a fake `MpvPlayer` and `PlayingServer`: what's loaded from the resume point, reports, tracks switched in mpv, the server's conversion after an mpv failure; the controls: play/pause, Space, →, Skip intro, Audio, the `A11y.silent` check), `MpvIntegrationTest` (the real libmpv through JNA plays colour bars into the software picture, pauses and seeks; skipped where there's no libmpv or ffmpeg, as on CI). Core `DesktopProfileTest`.
- libmpv for Windows: `tools/build-libmpv-windows.sh` (MSYS2 UCRT64 on windows-latest) builds FFmpeg 7.1.1 LGPL-only (`--disable-autodetect`, no postproc/avdevice; D3D11VA/DXVA2/NVDEC, Schannel, dav1d) and libmpv 0.40.0 `-Dgpl=false` (no Lua/JS/libarchive/rubberband/cdda/dvdnav/bluray/uchardet/vapoursynth/zimg/jpeg), with MSYS2's libass, FreeType, HarfBuzz, FriBidi, libplacebo, dav1d, Little CMS, shaderc, SPIRV-Cross and the Vulkan loader, into `desktop/resources/windows-x64` (git-ignored; Compose packages it as the app's resources). Every DLL must be on the script's licence list (`ALLOWED`; known GPL names stop it at once); it writes `licenses/DLLs.txt`, each package's licence files, FFmpeg's and mpv's, and `SOURCES.txt`. Keep `core/OpenSource` in step. Never use prebuilt mpv builds (most are GPL).
- Tests: `desktop/src/test` (`DesktopWindowTest`: Home and two-pane Settings against `FakeServer` with `runDesktopComposeUiTest`, pictures in `desktop/build/outputs/desktop`, the `A11y.silent` check); `testing/` is on its test path. `./gradlew :desktop:run` starts the app (on Linux too).
- Packaging (`desktop/build.gradle.kts`, Compose's `nativeDistributions`): an MSI (`packageMsi`: per-user install, directory choice, Start menu group and shortcut, `icons/nitrate.ico` drawn by `tools/generate-desktop-icon.py` from the Android launcher icon) and the app image (`createDistributable`) zipped as the portable copy with `portable.txt` beside `Nitrate.exe`; both carry a jlinked Java 21 runtime (modules listed in `modules(...)`, including `jdk.crypto.ec` for HTTPS and `jdk.accessibility` for screen readers) and the libmpv DLLs from `desktop/resources/windows-x64` (`appResourcesRootDir`; found at run time through `compose.application.resources.dir`). Versions follow the other apps: `NITRATE_VERSION_NAME`/`NITRATE_VERSION_CODE` from release.yml, the MSI's three-number version is the release's (`0.2.0`) or `0.0.<code>` for dev builds; dev builds are "Nitrate Dev" with their own fixed `upgradeUuid` (a separate app, as `.dev` on Android); never change either upgrade UUID (Windows upgrades installs by it). `NITRATE_DESKTOP_CHANNEL` (stable/dev) decides what the app updates to.
- Release (`release.yml`): the `windows` job (windows-latest) works out the name and channel by the same rule as the others, restores or builds libmpv (`msys2/setup-msys2`, cached on the script's hash), checks it loads and plays (`LibMpvLoaderTest` with `NITRATE_REQUIRE_MPV=1`, `MpvIntegrationTest` if ffmpeg is there), packages `nitrate-desktop-<name>.msi` and `.zip` in the same Gradle run as the checks (one compile); `windows-publish` adds them as soon as the release exists, never waiting for iOS, and the final `checksums` job writes SHA256SUMS for everything the release ended up with (the updater finds the MSI's line once that job has run). Build (`build.yml`): `./gradlew test` includes `:desktop:test` (fakes only; no libmpv on Linux CI); the desktop pictures join the screenshots artifact.
- Not done yet: code signing (SmartScreen warns on first run; needs a certificate in the release secrets and `signtool` after `packageMsi`), the Microsoft Store (MSIX), Windows on ARM (libmpv and the runtime are x64), theme music and new-episode/watch-party notifications (tray), Cast, picture-in-picture, the speakers question and upmix/dialogue boost (Android's audio processors; mpv's own filters could do it), refresh-rate matching, following another device's playback in Windows' media overlay (SMTC), Readium for EPUBs. The WINDOW output, HDR passthrough, bitstreaming over WASAPI, hardware decoding and the MSI/ZIP themselves have only been built for, not tried on, real Windows here: try them on a PC before relying on them. "This phone" in Settings' device-only headings is shared wording with the phone and iPad.
