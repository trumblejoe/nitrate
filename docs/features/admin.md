# Admin tools: metadata

Field locks, bulk editing, Identify, external IDs, images and library metadata settings.

Read CLAUDE.md first: its rules (keys, ids, privacy, licences, focus, server load) apply here too.

- Metadata locks and bulk editing (admins): field locks are core `admin/LockableField` (Jellyfin's `MetadataField` names only; `saveMetadata` drops anything else, since an unknown name makes the server refuse the save), toggled by the lock icons/chips in each app's Manage → Details. `admin/BulkEdit` (add/remove genres, tags, studios; set/clear age rating; lock/unlock fields or the whole item) reads, changes and saves each title's own metadata (`run` reports changed/unchanged/failed); each app's library "All" view has an admin "Select to edit" mode → edit, review (`describe`), apply, results (`BrowseViewModel.reload` after). Manage → Details starts with the title's file path (`ItemMetadata.path`, read only, from the item's `Path`; editors get it from the Companion's Access answer for titles they may edit; the phone can copy it), since a file's name often says what the title really is when fixing a match; it also shows the title's theme music (`MediaServer.themeMusicInfo`: own or the series', with a preview).
- Identify, IDs and images (admins, each app's Manage): Identify searches by name and year, or by an ID or link pasted into "Or an ID or link" (core `admin/ExternalIds.guess`: IMDb `tt…` anywhere, themoviedb.org/thetvdb.com pages, bare digits as TMDb, or TVDb for shows; sent as the search's `ProviderIds`, `MediaServer.remoteSearch(…, providerIds)`). External IDs in Manage → Details are the IDs the server's providers accept for that kind of title (`MediaServer.externalIdFields` = `Items/{id}/ExternalIdInfos`, `ExternalIds.fields` adds any other the title has) with the title's provider pages (`ItemMetadata.links` from `ExternalUrls`; phone "Open on …", TV listed). Images: kinds the providers offer (`imageProviders` = `RemoteImages/Providers`) plus any the title has; found images in the server's metadata language plus language-free ones by default (`remoteImages(…, provider, allLanguages = false)`, Jellyfin's `includeAllLanguages`), a provider filter and "All languages", biggest first (`RemoteImages.best`) with small ones marked (`RemoteImages.isSmall`: posters < 600 px wide, backdrops/thumbs < 1280; blocky on a TV); posters and other single kinds are replaced (Jellyfin keeps one of each), while a new backdrop (found or uploaded; Nitrate rotates through several, and the found list stays open) asks where it goes: core `admin/ImagePlacement` Replace main (becomes index 0, the old main deleted) / Add and make main (old main kept) / Add (`ImagePlacing.place`: adds, then moves the newest to 0 and deletes index 1 as asked); "Make main" moves an existing one to index 0 (`moveImage` = `Images/{type}/{index}/Index`); TV OK on an image asks Keep / Make main / Delete. Phone cards ask for `CARD_IMAGE_PX` (540) tall pictures, sharp at 3× density. Library metadata settings (Manage server → Libraries on both apps; core `admin/LibraryMetadata`): per library the dashboard's Manage library choices: metadata language and country (`metadataLanguages`/`metadataCountries` = `Localization/Cultures`/`Countries`), artwork saved into media folders (`SaveLocalMetadata`), NFO files (the `Nfo` metadata saver, shown only when the server has it), automatic refresh (Never/30/60/90 days), and per kind of item the metadata and image providers on/off in order (`LibraryMetadata.merge` of `Libraries/AvailableOptions` with the library's `TypeOptions`: saved order first, new providers after, defaults for kinds never set); saved over the library's own `LibraryOptions` JSON (`POST Library/VirtualFolders/LibraryOptions`), so everything else in it stays.

- Credits check (admins, Companion feature `creditsreport`; films and episodes): each app's Manage → Refresh has a "Credits check" line under Refresh that asks `MediaServer.creditsReport(itemId)` (`GET /Nitrate/Credits/{itemId}/Report`, `docs/features/companion.md`) and shows it in a few words (core `playback/CreditsReport.summary()`: where the credits start, any scene during or after them and whether someone speaks in it, the final credits after a scene, stretches not counted and why, how many subtitle lines voted or that the pictures decided alone). While the server reads the title (202, `reading`) the page asks again every 15 s (`CreditsReport.RECHECK_MS`). Phone and desktop add "Copy report", the whole JSON (one row of features per second) through `PlatformActions.copy`, for tuning; the TV has no clipboard and the report is too long for a QR code, so it shows the summary and says to copy the report from the phone. Metadata editors don't get it. Screenshots: TV and phone `manageCreditsCheck` (`FakeServer.creditsReportAnswer`).

## Metadata editors (Companion feature `metadata`)

Jellyfin 12.4 keeps saving items, applying matches, refreshing, changing images and listing external-ID fields for administrators (`RequiresElevation`). The Companion's logic lets chosen non-admin accounts do those for titles in chosen libraries, checking every request itself and logging every change. Reading (`GET /Items/{id}`, `/Items/{id}/Images`, `/Items/{id}/RemoteImages`, `/RemoteImages/Providers`, `POST /Items/RemoteSearch/{type}`) already works for any account, so editors call Jellyfin directly for those. The shell is unchanged; all of this is in `Nitrate.Companion.Logic` (`MetadataEditorController`, route `Nitrate/Metadata`). Choices made: editors get no library metadata settings; detail edits can be undone from the log; the log keeps 365 days; 30 changes a minute and 4 refreshes at once per editor; no admin notices; the role is called "Metadata editor".

Contract (JSON; ids dashless or dashed accepted, answered dashless; every call needs the Authorization header; answers are PascalCase like every Companion answer (`IsEditor`, `AllLibraries`, `LibraryIds`, `CanEdit`, `UserId`, `UserName`, `Id`, `AtMs`, `ItemId`, `ItemName`, `Kind`, `Summary`, `CanUndo`; the table writes them camelCase), bodies sent may use either case):

| Call | Who | Body / query | Answer |
| --- | --- | --- | --- |
| `GET /Nitrate/Metadata/Me` | anyone | | `{"isEditor":bool,"allLibraries":bool,"libraryIds":[…]}` (admins: true, true, []) |
| `GET /Nitrate/Metadata/Items/{id}/Access` | anyone | | `{"canEdit":bool,"path":string?}` (admins always true; `path` the title's file path, only with `canEdit` true; item not visible to the caller: 404) |
| `POST /Nitrate/Metadata/Items/{id}` | editor in scope | the item JSON as `GET /Items/{id}` gave it, read-only parts dropped (as `POST /Items/{id}`) | 204 |
| `GET /Nitrate/Metadata/Items/{id}/ExternalIdInfos` | editor in scope | | as Jellyfin's `/Items/{id}/ExternalIdInfos` |
| `POST /Nitrate/Metadata/Items/{id}/Apply` | editor in scope | `?replaceAllImages=bool`, body a `RemoteSearchResult` | 204 |
| `POST /Nitrate/Metadata/Items/{id}/Refresh` | editor in scope | the query of Jellyfin's `/Items/{id}/Refresh` | 204 |
| `POST /Nitrate/Metadata/Items/{id}/RemoteImages/Download` | editor in scope | `?type=&imageUrl=` | 204 |
| `POST /Nitrate/Metadata/Items/{id}/Images/{type}/{index}/Index` | editor in scope | `?newIndex=` | 204 |
| `DELETE /Nitrate/Metadata/Items/{id}/Images/{type}` and `/{index}` | editor in scope | | 204 |
| `POST /Nitrate/Metadata/Items/{id}/Images/{type}` | editor in scope | body base64 image, `Content-Type` image/jpeg, png or webp, at most 20 MB decoded | 204 |
| `GET /Nitrate/Metadata/Editors` | admins | | `[{"userId","userName","allLibraries","libraryIds":[…]}]` |
| `POST /Nitrate/Metadata/Editors/{userId}` | admins | `{"isEditor":bool,"allLibraries":bool,"libraryIds":[…]}` | 204 |
| `GET /Nitrate/Metadata/Edits` | admins | `?limit=50&before=<id>` | `[{"id","atMs","userId","userName","itemId","itemName","kind":"details|match|refresh|image","summary","canUndo":bool}]`, newest first |
| `POST /Nitrate/Metadata/Edits/{id}/Undo` | admins | | 204 (details only: the changed fields' old values back) |

Refusals: 400/403/413/415/429 bodies are literally `{"message":"…"}` (lowercase key); 401 and 404 are Jellyfin's usual ProblemDetails. 401 no token; 403 `{"message":"You can't edit this title"}` (not an editor, or the title's library is outside the scope); 404 the item isn't visible to the caller (Jellyfin's own library access, checked first), or an unknown user in `POST Editors/{userId}`; 413 image too large; 415 not JPEG/PNG/WebP, or the bytes don't match the declared type (a `data:…;base64,` prefix is accepted); 429 `{"message":"Too many changes: wait a minute"}` (the 30 a minute count every editor write: details, match, refresh, image download/upload/delete/move); 400 chapter images, a negative image index, a body that isn't base64, an `imageUrl` that isn't absolute http(s) or points at localhost, private addresses or server paths, Undo on a line that isn't details or is undone already, a bad library id in `POST Editors/{userId}`. `POST Items/{id}`: a field left out stays as it is, one sent as null is cleared (the apps send the whole round-tripped item); nothing editable changed → 204 and nothing logged. Apply's `replaceAllImages` defaults to true and Refresh's modes to None, so the apps always send them. Editors can't set paths or add images from server paths. The dashboard page's logic settings gain "Metadata editors" (type `users`, every library). The log is `metadata_edits` in `companion.db`.

How the apps use it: `MediaServer.account()` (`JellyfinAdmin.account`) reads `GET /Nitrate/Metadata/Me` for accounts that aren't admins when the Companion lists `metadata` (`companionHas`), into `AccountInfo.metadataEditor` (`admin/MetadataEditorScope`: `covers(libraryId)`; `AccountInfo.editsMetadata`, `canEditMetadataIn(libraryId)`), kept in `AppContainer.account` and cleared with it on switching or signing out. `MediaServer.canEditMetadata(itemId)`: admins true with nothing asked; editors `GET …/Items/{id}/Access` through the shared answers (`AnswerKind.COMPANION`, let go after anything sent; 4xx → false); anyone else false, nothing asked. `AppContainer.canManageMetadata(itemId)` gates Manage on each app's details More (TV `NitrateNavHost` → `DetailsScreen(onManage)`, phone `DetailsMoreSheet(canManage)`); bulk editing on a library's All list shows for `canEditMetadataIn(library)`. Editors get the same Manage tabs (Details with locks and External IDs, Identify, Images, Refresh) with a line saying the server's admins can see and undo their changes; Manage has no delete or library settings, TV's "Comic details" stays admin-only, and so do Manage server, Library health and the rest. Routing (`JellyfinAdmin.viaCompanion`: the account isn't an admin and the Companion lists `metadata`): `saveMetadata` (the same round-tripped JSON), `applyMatch`, `refreshItem`, `externalIdFields`, `downloadRemoteImage`, `moveImage`, `deleteImage`, `uploadImage` call `/Nitrate/Metadata/Items/{id}/…`; admins call Jellyfin's own endpoints; reads (item JSON, images, remote images, providers, remote search) are Jellyfin's for everyone. Refusals become `admin/MetadataEditRefused` with the server's message (`message`, else ProblemDetails `detail`/`title`, else Nitrate's words per status), which the Manage pages show ("Couldn't save: You can't edit this title"); nothing is reported done when refused. Admin calls: `metadataEditors()`/`setMetadataEditor(userId, scope)` (Manage server → Users) and `metadataEdits(limit, before)`/`undoMetadataEdit(id)` (Manage server → Metadata edits), both shown only with `metadata` (`docs/features/settings.md`). Tests: core `MetadataEditorsTest` (MockEngine: route by role, Me, Access kept, refusals); screenshots TV `editorDetailsMore`, `editorManageRefused`, `serverAdminEditors`, `metadataEdits`; phone the same names (`FakeServer.signInAsEditor`, `metadataRefusal`, `metadataEditorList`, `metadataEditLog`).
