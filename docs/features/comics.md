# Comics and books

Comic and EPUB reading, series, catalogs (OPDS/CLU) and ComicInfo editing.

Read CLAUDE.md first: its rules (keys, ids, privacy, licences, focus, server load) apply here too.

- Comics (Books libraries; reader plan: 1 reader, 2 page streaming/CBR/PDF, 3 Continue reading + series, 4 OPDS, 5 CLU, 6 EPUB via Readium, 7 ComicInfo editor + guided view): Jellyfin's `Book` items are `ItemKind.BOOK`; details pages show Read / "Continue from page N" (phone `PlaySection`, TV play button → `ComicRoute`). core `comics/Comics.kt`: `ComicPages.order` (image entries, natural order, no `__MACOSX`/hidden), `ComicInfo.parse` (series, number, title, `Manga` YesAndRightToLeft → `direction`, `DoublePage` pages), `Spreads.of` (cover alone, facing pairs, wide pages alone, flipped right to left; one per spread in one-page and vertical modes), `ComicProgress` (the page is the user data position, page n = n s via `saveUserData`; read at the last page, a read book stays read), `ReaderKeys.step` (arrows/taps in reading order), `ImageSize.of` (picture size from its header; wide = a spread on one picture), `ComicListing` (the plugin's answer). app-core `comics/ComicLibrary` (`AppContainer.comics`) opens a `ComicBook` (`title`, `pages` names, `widePages`, `startPage`, `page(i)` → a local file Coil loads, `fetchAll` = the rest of the book in one burst two at a time, which both readers start a second after opening, `saveProgress`) from a `PageSource`: with Companion feature `comics` page by page (`MediaServer.comicListing`/`comicPageUrl` = `/Nitrate/Comics/{id}` and `/Pages/{n}`; the listing is kept as `listing.json` so a fetched book reads offline), else the book's own file fetched once (`MediaServer.fileUrl` = `Items/{id}/Download`, with progress): CBZ through okio's `openZip` (multiplatform; wide pages from headers, kept in `wide`), PDF through the platform's `PdfPages` (`AppPlatform.pdfPages()`: core-android `AndroidPdfPages` = PdfRenderer, ios-app `IosPdfPages` = PDFKit; pages drawn 1800 px wide as JPEGs), CBR without the plugin a `ComicException` saying what's needed; everything under `cache/comics/<id>/`, the books opened most recently kept within 500 MB (`prune`, "opened" stamps). Readers: phone/tablet `ComicReaderScreen` (mobile-ui common: `HorizontalPager` of spreads, reversed for right to left; `ZoomBox` pinch/double-tap up to 4×, one-finger pan only while zoomed so swipes still turn; outer fifths of a tap turn, the middle shows the bars; page slider; `TwoUp` Automatic = two pages when wider than tall ≥ 600 dp; vertical strip as a `LazyColumn`; reading settings sheet), TV `ui/comics/ComicReaderScreen` (two pages by default; ◀▶ turn in reading order, OK zooms 2× from the corner reading starts, arrows pan while zoomed, Down/Menu the page strip with direction and Two pages chips, Back unzooms then leaves; FF/RW also turn). Both save the page 1.5 s after it settles and on leaving. Series: core `comics/ComicSeries` (a series is the server's series name, which Jellyfin's Bookshelf plugin reads from ComicInfo.xml, else the folder: `MediaItem.parentId`; `number` from the index else the name's last number, `label` "#12", `order`, `of` keeps one series out of a mixed folder, `next`, `after`, `continueReading`: half-read books and the next issue of series finished lately, one per series, newest first); `MediaServer.seriesIssues(book)` (the folder's books) and `continueReading(libraryId)`; rows `home/continue_reading` and, for Books libraries, `library/<id>/continue_reading`, `recently_added`, `unread`, `favorites`; details pages show "In this series" (`DetailsState.issues`, "This one"/Read/Reading); the readers offer the next issue on the last page (phone: a button in the bars, which come up there; TV: a label, and turning on past the end opens it, replacing the reader). Play on a book anywhere (phone `go`, TV gate) opens the reader. Comic catalogs (other servers; Companion feature `catalogs`, only offered when the admin has set one up): only the server's admin sets them up, on the plugin's dashboard page (`Catalogs/CatalogSettings` in the plugin configuration `ComicCatalogs`: name, OPDS or CLU, address, user/password or token), never in the apps, which never hold a catalog's sign-in. The plugin (`Api/CatalogsController`, `/Nitrate/Catalogs`) lists them without sign-in details (`CatalogInfo`), fetches through `Catalogs/CatalogFetcher` with the sign-in (`/Fetch?url`: only the catalog's own scheme/host/port, `CatalogAccess.Allows`, redirects followed by hand and only there; a catalog's 401/403 comes back as a 502 in words so the app's own sign-in isn't doubted), fetches whole books once into the server's cache folder (`catalog-books/`, most recently read within 2 GB) and serves them like its own through `ComicStore` (`/Book?url` listing, `/Book/Pages/{n}`, `/Book/File` for PDF/EPUB), and keeps each person's place per book (`Catalogs/CatalogPositions`, `/Position?book`, one database row per person and book, the 2,000 most recently read kept, the older `catalog-positions/` folder moved in once; the catalog's own progress is the household's shared account, so never written to and read only as a fallback). Core `catalogs/` (`ComicCatalog` id/name/url/kind; `CatalogLink` = `MediaServer.catalogLink`, core `jellyfin/JellyfinCatalogs`: `text`, `fetchUrl`, `book`, `pageUrl`, `fileUrl`, `position`/`savePosition`, Jellyfin's `authorization`; `CatalogClient` root/open(target)/search over a link giving `CatalogPage`s of `CatalogItem`s, sections with a `target` or books with a `CatalogBook`: page template, file, last read; `catalogClient(link)`), `OpdsCatalog` over core `opds/Opds` (OPDS 1.x Atom read by the small lenient `opds/Xml`; acquisitions ranked CBZ, PDF, EPUB, CBR; OpenSearch templates; OPDS-PSE stream links with `pse:count`/`pse:lastRead`, pages 0-based; `resolve` joins links like a browser) and `CluCatalog` (CLU's token API, `/api/v1`, tokens made in CLU's My Account → API Tokens: Recently added, To read, Favourites, Publishers → series → issues, all series with search by `q`; paging by `has_more`; covers `issue/{id}/cover` (CBZ only), the file `issue/{id}/download`). app-core `comics/CatalogStore` (`AppContainer.catalogs`): `catalogs()` from the server (and drops the old per-device `comic_*` keys, which held passwords, once), `client`, pictures fetched through the server into `cache/catalog-images`; `ComicLibrary.prepareCatalog` streams PSE pages (2000 px wide, through `/Fetch`) else the server's page-by-page copy of the file (CBR included), else the whole file (PDF, EPUB; EPUB places in thousandths), starting at the person's server-kept place else the catalog's. UI: phone Library tab "Comic catalogs" (only when the server has some) → `CatalogsScreen` (the server's list; none = `ComicCatalog.NONE_SET_UP`, which says where the admin adds them), `CatalogFeedScreen` (sections, cover grid, search, more on scrolling; CLU: "Open CLU" in the browser), `CatalogBookRoute` (the book as JSON) → `CatalogReaderScreen`; TV menu stop `MenuStops.COMICS` "Comics" (not in the default menu; added in Menu stops) and Settings → Your watching → Comic catalogs, `ui/comics/Catalogs.kt` (CLU's address as a QR code to manage it from a phone). EPUB: `ComicLibrary.prepare`/`prepareCatalog` give an `OpenedBook` (`Comic`, or `Epub`: the fetched file, this device's last locator from `locator.json`, the server's share read, `save`); an EPUB's place in Jellyfin is the share read as the position (`EPUB_SCALE` 1,000,000 = the end, read from 99.5%), a catalog EPUB's on the server per person in thousandths; EPUBs are fetched whole (small, and they read offline), not streamed. Readers hand an `Epub` to `AppPlatform.epubReader()` (`EpubReaderHost`): Android = core-android `books/AndroidEpubReader` + `EpubReaderActivity` (Readium 3.4, BSD-3, in `core/OpenSource`: `AssetRetriever` → `PublicationOpener` → `EpubNavigatorFactory` fragment in an AppCompat activity; dark, larger type on TV; ◀▶/page/FF/RW keys turn; position saved 1.5 s after it settles and on pause; starts at the saved locator else `locateProgression`), where the reader route steps aside; iPhone/iPad have no Readium yet (it builds only on a Mac; `useBookReader` and `iosApp/Drafts/ReadiumReader.swift` are ready for it), so mobile-ui `EpubScreen` (expect; iosMain `Epub.ios.kt`) is Nitrate's own: core `books/Epub` (container → package, spine chapters with sizes, `progression`/`place` by chapter sizes, `encode`/`decode` its own place) and a `WKWebView` per chapter from the book unpacked beside it, styled dark, scrolled to the place, with Previous/Next chapter. Book items carry `MediaItem.container` ("epub", "cbz"…); `ComicProgress.readLabel` gives "Continue from page N" or "Continue (34%)". ComicInfo editing (admins, Companion feature `comics`, CBZ only): the plugin's `Comics/ComicInfoEditor` (`PUT /Nitrate/Comics/{id}/Info`, a field → value map, empty removes; only `ComicInfoEditor.Fields`; rewrites a copy beside the book with the rest of ComicInfo.xml and the pages kept, then swaps it in, and queues a Jellyfin refresh) from `MediaServer.saveComicInfo`; core `ComicInfoFields` (`EDITABLE`, `MANGA` reading directions, `values`, `changes`); phone `ComicInfoButton` under Read on the details page, TV "Comic details" beside Manage (`ui/comics/ComicInfoEditor.kt`). Guided view (panel by panel): core `comics/Panels` (`find`: background from the page's edges, recursive cuts along gutters into tiers then panels, reading order incl. right to left, whole page when fewer than two; `fit`: the scale and shift that put a panel in the middle of the screen with the page drawn fitted), `ComicBook.panels(i, rtl)` from a small grey copy of the page (`AppPlatform.pictureReader()`: core-android `AndroidPictureReader`, ios-app `IosPictureReader`; cached per page; `canGuide`); phone reading settings "Panel by panel" (`GuidedPages`: taps at the edges step panels and on to the next page, the middle shows the bars), TV page strip "Panel by panel" chip (◀▶ and OK step panels; one page at a time meanwhile; the label says "panel n of N").
