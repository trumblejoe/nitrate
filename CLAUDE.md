# Nitrate

Jellyfin client for Android TV, Android phones/tablets, and (later) iOS. Kotlin (Multiplatform core), Compose, Media3, Ktor.

## Modules

- `:core` – Kotlin Multiplatform (jvm, iosArm64, iosSimulatorArm64). Nitrate's own models (`model/`), the `MediaServer` interface, the Jellyfin client (`jellyfin/`, Ktor + kotlinx.serialization), and all platform-neutral logic: rows, playback rules and test advisor, episode order, Fountain/.fadein, plugin logic. Code lives in `commonMain`; only the transfer server is in `jvmMain`. No `java.*`/`android.*` in `commonMain` — `./gradlew :core:compileKotlinIosArm64` catches it on Linux.
- `:app-core` – Kotlin Multiplatform (Android + iOS) app logic over `:core` shared by every app: `AppContainer` (built from an `AppPlatform`: DataStore files `AppStores`, HTTP engines, decoder probe, download scheduler, `ThemeMusic`/`NewEpisodeNotifier`/`AppUpdater` interfaces, network changes, timestamps), the stores (display, playback, session, plugins, profiles, search, backup; each takes its `DataStore`), `DataCache`/`LibraryCache` (`KeyValues`), view models, `SettingsSync`, `DeviceBackupManager`, `WritingStore`/`SharedWriting` (over `files/File`, okio), `RemoteControlHub` (`RemotePlayer`), `RowArtDrawing`. Packages keep their `dev.nitrate.android.*` names from before the move. `nowMs()` instead of `System.currentTimeMillis`.
- `:core-android` – Android side: `AndroidPlatform` (and `AppContainer(context, …)`), the DataStore files where Android always kept them (`AndroidStores`), OkHttp, `DeviceProbe`, `PlaybackSession` (Media3), `AndroidThemeMusic`, `AndroidNewEpisodeNotifier`, `AndroidUpdater`, WorkManager downloads, `PlaybackSession.report()`/`sendPlaybackReport(session)`.
- `:tv` – Android TV app (Compose for TV).
- `:mobile-ui` – the phone/tablet screens as a Compose Multiplatform library: every screen in `commonMain` (`MobileApp`, `LocalAppContainer`) except the player, which is per platform (`expect fun PlayerScreen`: Android's Media3 player and overlays in `androidMain`, Apple's player in `iosMain`). Platform needs go through `dev.nitrate.mobile.platform` (`Platform.kt` expect/actual: dates/numbers, `PlatformActions` copy/open URL/toast/volume, `PlatformBackHandler`, notification permission, image and file pickers, sound output, licence texts, artwork pixels, `ScriptTransfer`, `fullScreenDialog`, `windowSizeDp`); never call Android APIs from `commonMain` (`./gradlew :mobile-ui:compileKotlinIosArm64` catches it).
- `:mobile` – the Android phone/tablet app around `:mobile-ui`: activity, application, manifest, icons and the screenshot tests.
- `companion/` – Nitrate Companion, a Jellyfin server plugin (C#, .NET 10, against Jellyfin 12.4's NuGet packages; GPL-3.0 because it builds on Jellyfin's libraries) for what Jellyfin has no API for: watch-together chat and invites, single sign-on, household channels, watch partners and private accounts, shared screenplays, test clips, device summaries, scenes in the credits, intros and recaps as media segments, smart collections, files' timing, spoken-line search, comics page by page and comic catalogs, request timing, a lighter Home, Because you watched, a format index, the watch diary and insights. Apps find it with `GET /Nitrate/Companion` and hide features without it. Two projects: a small shell Jellyfin loads (`companion/Nitrate.Companion`: plugin, configuration, dashboard page, a catch-all `/Nitrate/*` controller, the tasks, segment provider and updater) and the logic (`companion/Nitrate.Companion.Logic`: every controller, hub, store and rule), loaded into a collectible context and swapped in without a restart from signed logic packages, in-memory state handed over under versioned keys; put new features in the logic and keep the shell's contract stable (`docs/features/companion-hotswap.md`). Nightly file-reading tasks keep results per file version in one SQLite database (`companion.db`, the server's own Microsoft.Data.Sqlite) and run one at a time. Released as `nitrate-companion-<v>.zip` plus a plugin-repository manifest (`tools/companion-manifest.py`); updates itself. Its plugin id is a storage key: never change it. The csproj sets only `<Version>` (the release stamps `-p:Version=0.1.0.<run>`): never pin `AssemblyVersion`. Test with `dotnet test companion/Nitrate.Companion.Tests`. Everything else: `docs/features/companion.md`.

- `:ios-app` + `iosApp/` – the iPhone/iPad app: `IosPlatform` and `MainViewController` showing `MobileApp`, built into the static `NitrateKit` framework that the XcodeGen project `iosApp/project.yml` (Swift host `NitrateApp.swift`) links. It plays in Apple's player, or in mpv (MPVKit's LGPL product only, never MPVKit-GPL) when the server would otherwise convert it. Linking needs macOS (`.github/workflows/ios.yml`, `ios-release.yml`, started by `release.yml`'s `ios-start` once the release exists, so a 30+ minute Mac build never holds up the next release); on Linux check with `./gradlew :ios-app:compileKotlinIosArm64`. Everything else: `docs/features/ios.md`.

- `:desktop` – the Windows app (Linux and macOS run it too): Compose for Desktop on the JVM showing `MobileApp` (`:app-core`/`:mobile-ui` have a `jvm("desktop")` target with `desktopMain` actuals; never call AWT/JVM APIs from `commonMain`), `DesktopPlatform`, the mpv profile (core `playback/DesktopPlayback`), the player (mobile-ui desktopMain `Player.desktop.kt` over `MpvPlayer`; `:desktop` `mpv/` is Nitrate's own JNA binding to libmpv, LGPL build only, from `tools/build-libmpv-windows.sh`), packaged as `nitrate-desktop-<name>.msi`/`.zip` by release.yml's `windows` job. Check with `./gradlew :desktop:test` (fakes; `MpvIntegrationTest` uses a real libmpv where one is installed); run with `./gradlew :desktop:run`. Never change the MSI `upgradeUuid`s. Everything else: `docs/features/windows.md`.

- `:ass-renderer` – libass (ISC) with FreeType (FTL), HarfBuzz (MIT) and FriBidi (LGPL), built static by `tools/build-libass.sh` into `libassJNI.so` behind a small JNI bridge (`AssRenderer`); without that build it compiles with no native code and reports itself unavailable. core-android `playback/AssSubtitles` (`AssSubtitleView`, `PlayerView.assSubtitles()`) draws ASS/SSA in its own layer inside the player's content frame (video frames untouched); `PlaybackSession.assTrack` gives the whole script plus fonts (the file's attachments, or a download's `assFiles`/`fontFiles`), and Media3's own subtitle view gets nothing for that track. Keep `core/OpenSource` in step.
- `:dovi-converter` – libdovi (quietvoid/dovi_tool's `dolby_vision` crate, MIT; Rust) built static by `tools/build-libdovi.sh` (needs rustup) into `libdoviJNI.so` behind `RpuConverter.toProfile81` (one RPU NAL unit, profile 7 → 8.1); without that build it reports itself unavailable and profile 7 plays as its base layer. Keep `core/OpenSource` (libdovi and the shipped crates) in step.
- `:ffmpeg-decoder` – Media3's FFmpeg audio extension (Apache 2.0 sources; its video renderer is an upstream stub, left out) plus Nitrate's own software video decoder (`dev.nitrate.ffmpeg.FfmpegVideoDecoder`/`FfmpegVideoRenderer`, JNI in `ffmpeg_video_jni.cc`: H.264 incl. 10-bit, MPEG-2, MPEG-4 Part 2, VC-1; frames as 8-bit 4:2:0 drawn into the Surface as YV12; up to 1080p) over FFmpeg built LGPL with only those decoders (DTS, TrueHD, AC-3/E-AC-3, ALAC; ARM only) by `tools/build-ffmpeg.sh`. Without that build it compiles with no native code and reports itself unavailable. Players use audio via `EXTENSION_RENDERER_MODE_ON` and add the video renderer after MediaCodec's (both only when the device has no decoder); `DeviceProbe` counts them (`SOFTWARE_VIDEO_DECODER`, `VideoCodecCaps.softwareTenBit` for Hi10P over 8-bit hardware), and the profile keeps software video to 1080p and progressive (`VideoLimit.progressiveOnly`, `tenBitMaxHeight`), VC-1 MKV-only (`MATROSKA_ONLY_VIDEO`). Never enable GPL or non-free FFmpeg parts; keep `core/OpenSource` (the licences pages) in step with what ships.

## Commands

- Build: `./gradlew assembleDebug` (with DTS/TrueHD decoding: run `tools/build-ffmpeg.sh` first; needs the NDK named in `ffmpeg-decoder/build.gradle.kts`)
- Unit tests: `./gradlew test :core:jvmTest` (Gradle's build cache and up-to-date checks skip modules whose inputs didn't change, so never add `cleanTest`; `--rerun` after a test task forces it). Run only the tests for what changed (one class or a few screenshot tests: `./gradlew :tv:testDebugUnitTest --tests '*ScreenshotTest.remote*'`) plus compiling the touched modules; never the whole set locally, not before committing, merging or releasing: GitHub's Build runs it on every push and Release refuses to publish when it fails (then fix and push again). The iOS check (`./gradlew :mobile-ui:compileKotlinIosArm64`, `:ios-app:compileKotlinIosArm64`) only when shared code changed (core, app-core, mobile-ui `commonMain`/`iosMain`), once per batch of work. Background agents follow the same rule; prefer doing small changes directly over a worktree (each copy recompiles everything). Modules build and test side by side (`org.gradle.parallel`); use the default workers (4 here).
- CI: `build.yml` tests only what a push changed (`tools/changed-parts.py`: job `android` for the Gradle side, `companion` for the plugin; documentation, the Swift host and the release workflows (`release.yml`, `ios-release.yml`) need neither; `build.yml` and `changed-parts.py` count for both). A change to the workflows alone needs a push, not a release: a release always builds every app afresh, since each carries its own version for the updaters. `release.yml` builds the release at once, side by side with Build, then reads those two jobs' results on the same commit ("Tested already?", waiting if they're still running) and skips their tests when they passed, refuses to release when one failed, and, when Build skipped a part or never ran (a tag elsewhere), counts the last earlier commit whose Build passed it if nothing of that part changed since (`changed-parts.py` over GitHub's compare), else tests it itself. On GitHub (`CI` set) a failed test runs once more (`org.gradle.test-retry`, root `build.gradle.kts`): a flake passes, a real failure fails twice; locally a failure stays a failure. Keep the job names `changes`, `android`, `companion`: release reads them.
- If Maven Central returns 429, retry with `--max-workers=2`.

## Rules that are easy to break

- Never rename a stored key or id: row keys (`MediaRow.key`, `AppRows` keys, `home/up_next_together`…), plugin ids (`NitratePlugin.id`, the Companion's plugin id), display-settings entry names and the stored names of `DisplayPrefs` fields (`tvHome`, `tvLibraryLayout`…). Saved settings are read by them.
- Playback settings are per device and never synced; display settings are per user and sync through `SettingsSync` (`docs/features/playback.md`, `docs/features/settings.md`). Profile PINs, "ask who's watching" and each device's choice of display profile are device-only too.
- Privacy: private accounts are never listed or findable, and nothing may tell an inviter whether an account exists (an invite to a typed name always reads "sent"); standings and caches belong to the account and are cleared on switching or signing out; chat history is shown only when asked for, and only messages the caller was there for (in the message's audience: who was in the conversation when it was written; notes brought into a live session are never kept for those outside it); never send the user's details to outside services (`docs/features/partners.md`, `docs/features/companion.md`).
- Licences: FFmpeg built LGPL only (never GPL or non-free parts), mpv only through MPVKit's LGPL product (iOS) or `tools/build-libmpv-windows.sh`'s `-Dgpl=false` build with its DLL licence list (Windows; never prebuilt mpv builds), verses only from public-domain translations, effect footage only public-domain/CC0/CC BY(-SA), effects drawn originally with no franchise names, logos or emblems; keep `core/OpenSource` (the licences pages) in step with what ships.
- Server load: nothing network-bound is awaited before Home appears; Home and library rows load as independent `RowJob`s (OkHttp allows 16 requests per server) and are revealed whole (`PageReveal`); hidden rows are never queried; lists go through the shared `AnswerCache`; "Because you watched" asks for similar titles sparingly; background readers use `watchingRows`, never the whole page (`docs/features/browsing.md`, `docs/features/diagnostics.md`).
- Every single-item play goes through the guards (`PluginRegistry.checkBeforePlay`, TV `PlaybackGate`); Jellyfin 12.4 rejects `api_key` query auth, so always send the Authorization header.

## Conventions

- Screens use `:core` models (`MediaItem`, `PlaybackPlan`…) and talk to the server only through `MediaServer`. Only `core/jellyfin` knows Jellyfin's API.
- Ids are strings (dashed lowercase UUIDs, as stored in settings and row keys) and times are milliseconds; conversion from Jellyfin's dashless ids and ticks happens in `core/jellyfin/Mappers.kt`.
- Jellyfin JSON is PascalCase (`JellyfinJson` maps camelCase DTO fields). DTOs are internal and hold only fields Nitrate reads. When calling a new endpoint, add it to `tools/trim-openapi.py`, regenerate `core/src/jvmTest/resources/jellyfin-openapi.json`, and exercise it in `JellyfinContractTest`, which checks paths, query parameters, body fields and enum values against the spec.
- Dependency versions live in `gradle/libs.versions.toml`.
- Rows (`core/rows/MediaRow`) have a stable `key` such as `home/next_up` or `library/<id>/recently_added`. Display settings are saved against it, so never rename a key.
- Admin calls live in `core/jellyfin/JellyfinAdmin.kt`. Item updates and user policies round-trip the server's own JSON (never rebuild them from DTOs) and drop read-only parts first (`READ_ONLY_ITEM_FIELDS`; 12.4 can't parse its own `Trickplay` back). Admin UI shows only when `AppContainer.account` says `isAdmin`.
- Shared test fixtures (`FakeServer`, sample art) live in `testing/` and are on both apps' test source paths.
- Accessibility: every screenshot test (TV `shoot`, phone `shoot`) fails if anything that can be focused or tapped would be read out as nothing (`testing/A11y.silent`: no words of its own or inside it). Picture-only cards say `MediaItem.spokenTitle` (an episode as "Show, season 2, episode 5", never its name); a switch or swatch whose words sit beside it takes them with `Modifier.labelled` (phone) or the whole line is the toggle (`toggleable`, the switch's own `onCheckedChange = null`); icons without visible words (TV rail closed) carry the stop's name; sliders and maps give a `stateDescription` (where you are, what's chosen); invisible focus holders are named for what they're doing.
- TV: use `androidx.tv.material3` components so focus and D-pad behaviour are correct; every interactive element must be reachable and visibly focused with a D-pad. Text entry is `TvTextField`, which only opens the keyboard on OK and gives Up/Down back to the D-pad. TV player controls (`ui/player/PlayerControls.kt`): every button is a `PlayerButton` (alike until focused, then white and larger; play/pause round with its symbol); with the controls hidden, OK or an arrow only brings them back; Back closes the topmost thing (handled as a key by the player's root `onKeyEvent` → `goBack()`, as well as `BackHandler`: left to Compose, an unhandled Back first moves focus out of its group, which made More and Info take two presses; a More Settings page consumes Back itself to go back one step) (pop-up, side panel), then hides the controls (playing or paused), then leaves; closing a pop-up keeps the controls up and returns focus to the button that opened it (`ControlFocus`); sub-pages inside a pop-up go back one step; focus is never left nowhere: whatever had it going away (a banner, Up Next, a pop-up) hands it to `refocus()` (the controls' last button, else the player), a guard puts it back if it's lost with nothing open, and banners never take it from More, Info or a dialog (`CreditSceneBanner(takeFocus)`); Back closes what's open before a banner; buttons not yet usable still show focus (outlined, larger); Info is a panel over the video in place of the controls, sized to the screen and scrolled with ▲▼ (`PlaybackInfoPanel`); the remote's Menu key toggles the controls (and closes More or Info back to them); the More button (or Down from the buttons) opens More: `MoreSheet`, a panel across the bottom with the video above, tabs (◀▶; a tab shows when focused; in the order Settings, Chapters, Cast, Extras, then the season's episodes (or the collection's films) last so opening it shows no spoilers; opens on the tab used last, never on the episodes or collection) and one tab's `CardRow` or list below, built by `moreTabs`: the season's episodes (wrapping round, "Now" on the one playing, stills blur by `spoilerStill`, watched/progress marks per `DisplayPrefs`; OK plays through `onPlayNext`) or the films of the collection (`NextInCollection.saga`), Chapters (numbered placeholder without a picture), Cast (only with `DisplayPrefs.cast`; OK opens `PersonDialog` over the video: photo, role, born, biography scrolled with Up/Down, "Also in your library"), Extras (`MediaServer.extras`, the show's for an episode; OK plays on top via `onPlayExtra`, and Back/its end returns to the same spot through the entry's saved `resumeAt`; not in a Group Watch Session or SyncPlay group) and Settings (`PlayerChoicesTab` from `rememberPlayerChoices`, laid out like Settings: each line's name with what's on now under it, chips beside; pages end in ›: speed, sound, sleep timer, subtitle timing, audio sync, refresh rate (a per-playback `FrameRateMatch` for `FrameRateMatcher`, with `refreshNote` on how the video looks at the TV's rate now), each default from the device's own settings tagged DEFAULT; changes are for this playback, "Make default" saves them; Speakers, Second subtitles and Find subtitles as pages that Back leaves: a page takes focus as it opens, and Back returns it to the chip that opened it, the list's `focusRestorer` held off meanwhile); not in easy mode.
- Plugins are compiled in (no downloaded code). Logic lives in `:core` (`NitratePlugin`, `PlaybackGuard`) and is registered in `AppContainer.plugins`; each app adds its screens for a plugin by `pluginId` (TV: `TV_PLUGIN_UI`). A plugin's `id` is a storage key: never change it.
- Every single-item "play" goes through `PluginRegistry.checkBeforePlay` (TV: `PlaybackGate`) so guards run; queued playback (playlists) deliberately bypasses it. Play on a show or season card plays an episode (core `playback/PlayTargets`: a show its `nextUpFor`, else its first season's first unwatched; a season its first unwatched, else its first), resolved before the guards in TV `PlaybackGate.play` and the phone's `guarded`.
- Easy mode (`DisplayPrefs.easyMode`, per display profile; first switch in Display on both apps): phone `ProvideDisplayPrefs` scales density ×1.1 and text ×1.15 (TV: text ×1.2 only, layouts are fixed-width); phone tabs Home/Search/Library/Settings (Downloads once there are some), no "Your pages"; TV menu keeps `MenuStops.essential` stops (overlay, rail, bar and dial) and the profile corner (Search, and the avatar's panel: Switch user, Settings, Sign out) on every menu page (with the overlay, the same Search and avatar in its pop-up's top row); players drop swipes/pinch, chapters, chat, Info, More (phone `VideoSurface(simple)` hides previous/next); sign-out (both apps) and playlist removal (phone) ask first. New screens should honour it where they add menus or destructive actions.
- Hidden gestures are shortcuts, never the only way in. TV: the menu has a "Customize this page" stop (pencil, `CUSTOMIZE_STOP`, just before Settings, or last where Settings is in the profile corner, on every `MainMenu` page with a page key; not in easy mode) the way to edit every page, opening its Customize panel (`MainMenu` holds the `CustomizeHost` and hands it to `ThemedPage(host)`; `CustomizeHost.openPage`, with `lastRow`/`lastRows` told by `RowsPage`/`FullArtPage` as focus moves, so "This row" is there too). The remote's Menu key always opens and closes the menu (overlay, rail, bar or dial; from the profile corner too), nothing else; the profile corner (Search, avatar) is reached with Up from the page's top (the overlay has none: its pop-up's top row holds them, and it opens with Menu or the arrow chosen in "Opens with"). A title in one of the user's watch groups has "Watch group…" in its details page's More on both apps (the same choices as holding OK / a long press on its card: TV `TogetherChoicesDialog(onCustomize = null)`, phone `TogetherChoicesSheet`). Holding OK on Switch user has Settings → Switch user. New hold/long-press actions need a visible route too.
- Other Jellyfin clients (e.g. Wholphin, GPL) may inspire features, but never copy their code.

## Feature notes

The long descriptions of each feature live in `docs/features/`. Read the one for the area you're changing, and keep it up to date when you change that area:

- `docs/features/tv-ui.md` – TV pages, rows and navigation: How the TV app's pages are built: rows, full art, menu, tabs, Customize, layouts and the small TV-only extras. The TV focus rules stay in CLAUDE.md.
- `docs/features/phone-ui.md` – Phone and tablet UI: The phone/tablet look and layout (mobile-ui common, so iOS too), widgets, notifications and the player's swipes.
- `docs/features/browsing.md` – Browsing, details, search and server load: Library browsing, details pages, search, lists and playlists, live TV, and how pages load without loading the server.
- `docs/features/settings.md` – Settings, accounts, profiles and backups: Display profiles, how Settings is laid out and searched, first-run setup, device backups, accounts and servers, self-update.
- `docs/features/playback.md` – Playback: Deciding how things play, tracks, sound (dialogue boost, upmix), refresh rate, Dolby Vision 7, 3D, credits scenes, Up Next, recaps, downloads and the player's Info.
- `docs/features/diagnostics.md` – Diagnostics and troubleshooting tools: Playback fixer, predictions, test plays and the TV check, reports, server settings, library health, stats, speed check and the query analyzer.
- `docs/features/remote.md` – Remote control, Cast and SyncPlay: The phone as a remote, Google Cast through Jellyfin's receiver, and what's left of SyncPlay (compatibility only; watching now together is a Group Watch Session, partners.md).
- `docs/features/partners.md` – Watch groups and Group Watch Sessions: Watch groups (people and their titles), each group's own record and marks (apart from the user's Watched; a page is in a group only when entered from it), group resume points, schedules and the Together switch, private accounts (privacy rules here are strict), Home's Watching together row, which group a playback counts for, the player's group button and panel, Group Watch Sessions, and group chat (chat histories) and invites.
- `docs/features/companion.md` – Nitrate Companion (server plugin): What the plugin does and how the apps use it.
- `docs/features/writing.md` – Shared screenplays and script story: Writing: OT sessions, ownership and sync, scenes, lists, the story map and history.
- `docs/features/comics.md` – Comics and books: Comic and EPUB reading, series, catalogs (OPDS/CLU) and ComicInfo editing.
- `docs/features/music.md` – Music, audiobooks and Android Auto: The listening player, audiobooks, Android Auto, lyrics.
- `docs/features/effects.md` – Effects, page themes, pre-rolls and verses: TV effects: card effects, page themes and occasions, backdrops, pre-rolls and the public-domain verses.
- `docs/features/admin.md` – Admin tools: metadata: Field locks, bulk editing, Identify, external IDs, images and library metadata settings.
- `docs/features/ios.md` – iPhone and iPad: The iOS app, its players (Apple's and mpv) and what isn't on iOS yet.
- `docs/features/windows.md` – Windows (desktop): The desktop app from the shared screens, its mpv player, profile and packaging.
