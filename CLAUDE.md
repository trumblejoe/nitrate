# Nitrate

Jellyfin client for Android TV, Android phones/tablets, and (later) iOS. Kotlin (Multiplatform core), Compose, Media3, Ktor.

## Modules

- `:core` – Kotlin Multiplatform (jvm, iosArm64, iosSimulatorArm64). Nitrate's own models (`model/`), the `MediaServer` interface, the Jellyfin client (`jellyfin/`, Ktor + kotlinx.serialization), and all platform-neutral logic: rows, playback rules and test advisor, episode order, Fountain/.fadein, plugin logic. Code lives in `commonMain`; only the transfer server is in `jvmMain`. No `java.*`/`android.*` in `commonMain` — `./gradlew :core:compileKotlinIosArm64` catches it on Linux.
- `:app-core` – Kotlin Multiplatform (Android + iOS) app logic over `:core` shared by every app: `AppContainer` (built from an `AppPlatform`: DataStore files `AppStores`, HTTP engines, decoder probe, download scheduler, `ThemeMusic`/`NewEpisodeNotifier`/`AppUpdater` interfaces, network changes, timestamps), the stores (display, playback, session, plugins, profiles, search, backup; each takes its `DataStore`), `DataCache`/`LibraryCache` (`KeyValues`), view models, `SettingsSync`, `DeviceBackupManager`, `WritingStore`/`SharedWriting` (over `files/File`, okio), `RemoteControlHub` (`RemotePlayer`), `RowArtDrawing`. Packages keep their `dev.nitrate.android.*` names from before the move. `nowMs()` instead of `System.currentTimeMillis`.
- `:core-android` – Android side: `AndroidPlatform` (and `AppContainer(context, …)`), the DataStore files where Android always kept them (`AndroidStores`), OkHttp, `DeviceProbe`, `PlaybackSession` (Media3), `AndroidThemeMusic`, `AndroidNewEpisodeNotifier`, `AndroidUpdater`, WorkManager downloads, `PlaybackSession.report()`/`sendPlaybackReport(session)`.
- `:tv` – Android TV app (Compose for TV).
- `:mobile-ui` – the phone/tablet screens as a Compose Multiplatform library: every screen in `commonMain` (`MobileApp`, `LocalAppContainer`) except the player, which is per platform (`expect fun PlayerScreen`: Android's Media3 player and overlays in `androidMain`, Apple's player in `iosMain`). Platform needs go through `dev.nitrate.mobile.platform` (`Platform.kt` expect/actual: dates/numbers, `PlatformActions` copy/open URL/toast/volume, `PlatformBackHandler`, notification permission, image and file pickers, sound output, licence texts, artwork pixels, `ScriptTransfer`, `fullScreenDialog`, `windowSizeDp`); never call Android APIs from `commonMain` (`./gradlew :mobile-ui:compileKotlinIosArm64` catches it).
- `:mobile` – the Android phone/tablet app around `:mobile-ui`: activity, application, manifest, icons and the screenshot tests.
- `companion/` – Nitrate Companion, a Jellyfin server plugin (C#, .NET 10, against Jellyfin 12.4's NuGet packages; GPL-3.0 because it builds on Jellyfin's libraries) for what Jellyfin has no API for: chat in SyncPlay groups (`/Nitrate/Chat`, long polling), single sign-on (`/Nitrate/Sso`, open), household channels (`/Nitrate/Channels`), watch partners and private accounts (`/Nitrate/Partners`, `/Nitrate/Privacy`) and shared screenplays (`/Nitrate/Scripts`: owner + invited members, compare-and-set edits on the latest version, long-polled edits and cursors, kept in the plugin's database: `Scripts/DbScriptStorage`, every accepted edit one `script_edits` row, the whole script (`scripts` row) written at most every 30 s while people type and at once otherwise, the edits after the last whole copy replayed on start; the older `scripts/` folder moved in once), TV and receiver check clips (`/Nitrate/TestClips`, embedded from `TestClips/`), household device summaries (`/Nitrate/Devices`, admins read), watch-together invites (`/Nitrate/Together/Invites`, `Together/InviteHub`, in memory for 3 hours), scenes in the credits (`/Nitrate/Credits/{itemId}`, `Credits/CreditFinder` = the apps' thumbnail reading in C#, keep in step; `CreditScanner` = the nightly "Find scenes in the credits" task: every film and episodes tagged with a stinger, the last 30% decoded keyframes-only by the server's ffmpeg into 48×27 grey grids with their `showinfo` times, held onto a 5 s grid; results per file version in the plugin's database (`Storage/CompanionDb`, see below), with `CreditFinder.FinalCredits`: the last stretch of credits running to the end, after any scene, across breaks shorter than a scene, stored as `OutroStartMs`/`OutroEndMs`; `CreditResult.Format` makes older results be read again), intros (`Intros/IntroScanner` = the nightly "Find intros" task: the opening 30% (3–10 min) of each episode's sound read once by the server's ffmpeg as 8 kHz mono into an `AudioPrint` (32-bit band-energy-change frames every 64 ms, kept per file version in the plugin's database), each season's episodes compared with their neighbours by `IntroFinder` (the longest shared stretch of 15–150 s, edges trimmed to where matches are dense; results in the plugin's database), plus "Previously on…" recaps by `RecapFinder`: the opening before the intro (else its first 4 min) matched clip by clip (`AudioPrint.SharedRuns`, ≥ 2 s each, gaps ≤ 8 s, matches inside an earlier episode's intro ignored) against the whole sound of the 3 episodes before it in the show (whole-sound prints kept only for each show's last 3 episodes, `IntroStore.KeepWholeOnly`, so a new episode never has its predecessors read again; a recap is only looked for in a new or changed episode, the others keep theirs), starting within 30 s, ≥ 15 s long, at least half clips; `Segments/CompanionSegmentProvider` (an `IMediaSegmentProvider`, "Nitrate Companion", switchable per library; `RunSegmentPluginProviders` after a find) hands Jellyfin each episode's Recap and Intro and each title's final credits as an Outro, so Skip Intro/Recap/Credits and Up Next work in every app with no app change, and an Outro never holds a mid- or post-credits scene (core `CreditScenes` takes the earlier of an Outro and the server's credits start, and an Outro running to the end is no scene marker); seasons are looked at again only when an episode is new or changed), smart collections (`SmartCollections/SmartRule` in the plugin configuration, edited on its dashboard page: all set conditions must hold, lists match any entry; `SmartCollectionUpdater`, "Update smart collections", nightly and via `SmartCollectionWatcher` ten minutes after films/shows/episodes are added or removed, keeps one real Jellyfin collection per rule through `ICollectionManager`, remembered in the plugin's database (`companion.db`, `pairs` kind `smart-collections`; the older `smart-collections.json` moved in once) and made again if deleted; a removed rule leaves an ordinary collection), files' timing (`Timing/TimingScanner`, the nightly "Check files' timing" task: the server's ffprobe reads each film's and episode's streams' start times and the packets of its first 5 minutes, no decoding; `TimingFinder` names a sound/picture start offset ≥ 100 ms, gaps in the sound ≥ 300 ms or picture ≥ 500 ms, timestamps going backwards and a variable frame rate; per file version in the plugin's database; `GET /Nitrate/Timing` lists titles with issues, admins only; feature `timing`), spoken-line search (`/Nitrate/Lines`, `Lines/LineIndex`: SQLite FTS5 in `lines.db`, using the server's own Microsoft.Data.Sqlite, never shipped; filled by the "Index spoken lines" scheduled task, nightly and incremental, via `ISubtitleEncoder` as SRT) and comics page by page (`/Nitrate/Comics/{itemId}` listing format, pages with sizes from `Comics/ImageHeader` and ComicInfo.xml, `/Pages/{n}`; `Comics/ComicStore`: CBZ read in place, CBR/CB7/CBT unpacked once with SharpCompress (MIT, shipped beside the plugin: `tools/companion-manifest.py` `ASSEMBLIES`) into the server's cache folder, the most recently used within 4 GB; PDF and EPUB only named, the apps take the whole file; `EnableComics`; `ComicPages` keeps in step with core's) comic catalogs (`/Nitrate/Catalogs`: OPDS/CLU catalogs the admin sets up on the dashboard page, fetched with their sign-in only on their own server, books served page by page, each person's place kept; see Comics below) request timing for the apps' query analyzer (`/Nitrate/QueryTimes`, feature `querytimes`; `/Household` for admins: every person's tagged requests by shape = method, path with `{id}`, parameter names never values, `QueryTimeStore.ShapeOf`/`Household`), lighter Home (`Api/HomeController`, all from the server's database, never media files: `/Nitrate/Home` = Continue Watching, Next Up, "Latest in…" for film/show libraries and Because you watched in one answer of Jellyfin's own `BaseItemDto`s, feature `home`; `/Nitrate/Because` from `Recommendations/BecauseBuilder`, the nightly "Make Because you watched" task (2:00; `BecauseRows` = the apps' rules; rows kept in memory only, `BecauseStore`, a few dozen ids per person; after a start `BecauseWarmup` makes them again in the background, 3 minutes in, for everyone who watched something in the last 30 days, one at a time; asked before theirs is ready, a person gets none that once and theirs is made then, never a wait (`For`/`BuildSoon`); over 30 h old they're remade in the background; watched titles left out when read), feature `because`; the app never keeps an empty answer from it; `/Nitrate/Formats` from `Formats/FormatIndex`, each title's codecs/bit depth/range/DV profile/sound kept in memory and forgotten on `ItemAdded/Updated/Removed`, shows from their episodes, feature `formats`) and the watch diary (`/Nitrate/Diary`, `Diary/DiaryHub`, one database row per watch, `Storage/DbDiaryStorage` writing only what changed, the older `diary/` folder moved in once; `DiaryRecorder` hosted service records `PlaybackFinished` saves that ended played with no resume point). Every file-reading nightly task (Find intros 1:30, Index spoken lines 3:00, Find scenes in the credits 4:00, Check files' timing 4:30) keeps its results per file version and reads a file again only when it changes; one runs at a time (`Scanning/FileReading.Gate`), and a file that couldn't be read waits a day, then a week, then a month before another try, or until it changes (`Scanning/ReadFailures`). These results, the intro task's fingerprints and the read failures live in one SQLite database, `companion.db` in the server's data folder (`Storage/CompanionDb`, the server's own Microsoft.Data.Sqlite, WAL; tables `results` (kind, item, json), `prints` (item, whole, version, blob), `failures` (task, key, json), `pairs` (kind, key, value): smart collections' rule → collection, and the watch partners' state as one row, `DbPartnerStorage`, the older `partners.json` moved in once; `records` (kind, owner, key, json, at): diary entries, catalog places and household device reports, `Storage/DbDeviceReportStorage` one row per person and device, the older `devices.json` moved in once; `scripts`/`script_edits` for screenplays), one row written per title, never a whole file rewritten; the older `credits.json`, `timing.json`, `intros.json` and `intro-prints/` are moved in once on start and deleted (`ImportResults`/`ImportPrints`). Because you watched (2:00) and smart collections (5:00) use the database only. Insights in the same database (`Insights/`, `Api/InsightsController`; `records` kinds below): request timing trends (`QueryTrendRecorder` hourly folds `QueryTimeStore` into one `query-day` row per day and shape, a log2 histogram, 90 days; `GET /Nitrate/QueryTimes/Trends`, admins), wrong-segment votes (`POST /Nitrate/Segments/Feedback`, `segment-vote`: an admin's vote or two people's marks the title's intro/recap/final credits rejected (`IntroRejected`/`RecapRejected`/`OutroRejected`, read through `Effective()`, kept across rescans of the same file version) and re-runs the segment providers; feature `segmentfeedback`), real watch time (`SittingRecorder` from the server's playback events, any app: one `sitting` row per sitting of a minute or more, pauses not counted, `GET /Nitrate/Watching`; feature `watching`), playback trouble (`POST /Nitrate/Problems` failed/converted per device, `problem`, 90 days; `GET` admins, by title; feature `problems`), moments (`/Nitrate/Moments`, `moment`, 500 per person, optionally shared with one of the person's watch groups, whose members see it; feature `moments`) and watch-together chat history (each chat message sent is also kept as a `chat` row under what the group was playing with the group's members at the time, 3 years, `KeepChatHistory` on the dashboard page (on by default); `GET /Nitrate/Chat/History?itemId` returns only messages the caller was there for; feature `chathistory`). Apps find it with `GET /Nitrate/Companion` and hide features without it. Released as `nitrate-companion-<v>.zip` plus a plugin-repository manifest on the `companion-repo` release (`tools/companion-manifest.py`). Updates itself: `Updates/SelfUpdater` asks the server's plugin repositories every 6 hours (first 10 minutes after start) and installs a newer version of itself through `IInstallationManager` unless auto-update is off on its plugin page; with `RestartForUpdates` (off by default, dashboard "Finish updates by restarting at night") it restarts the server (`ISystemManager.Restart`) once a newer copy waits for a restart, in the two hours from `RestartHour` (server time, default 4) and only with nothing playing (`UpdatePolicy`). The csproj sets only `<Version>`, so the release's `-p:Version=0.1.0.<run>` stamps the DLL too: Jellyfin compares the running DLL's version with meta.json and the repository's, so never pin `AssemblyVersion`. Its plugin id is a storage key: never change it. Test with `dotnet test companion/Nitrate.Companion.Tests`.
- `:ios-app` + `iosApp/` – the iPhone/iPad app: `IosPlatform` (DataStore files in Documents, Darwin engines, `appleCapabilities` = `PlayerEngine.APPLE`: MP4/MOV direct play, fragmented-MP4 HLS, subtitles as WebVTT in HLS or burned in; `IosThemeMusic`; `IosNewEpisodeNotifier`: local notifications, checked in a `BGAppRefreshTask` (`AppDelegate` in `NitrateApp.swift`, `MainKt.checkNewEpisodes`) and after library changes, taps open the item via `IosApp.openItem`; no downloads or self-update yet) and `MainViewController` showing `MobileApp`, built into the static `NitrateKit` framework that the XcodeGen project `iosApp/project.yml` (Swift host `NitrateApp.swift`) links. The iOS player (`mobile-ui` iosMain `ApplePlayerSession`, `Player.ios.kt`) plays in Apple's player, or in mpv when the server would otherwise convert it for Apple's (`resolvePlayback(deviceCaps = Mpv.capabilities(...))`, `PlayerEngine.MPV`: every container, styled/image subtitles as they are; `MpvTracks` maps server stream indices to mpv aid/sid): mpv is MPVKit's LGPL product only (never MPVKit-GPL), driven from Swift (`iosApp/Nitrate/MpvPlayerView.swift`, `NitrateMpvPlayer`: Vulkan over MoltenVK, VideoToolbox) through ios-app `NitrateMpv`/`useMpv` (`close()`, not `release()`, which NSObject has) into mobile-ui `Mpv.factory`, with Nitrate's own controls (`MpvControls`). Both get the shared overlays (`PlayerOverlays.kt`: skip, Up Next, credits banner, `TrackPicker`); tracks via `trackSetup`/`pickTrack` (mpv switches in place for files played as they are). Linking needs macOS: `.github/workflows/ios.yml` builds an unsigned `nitrate-ios-<name>.ipa` for sideloading on pushes to `ios-app`, and `release.yml`'s `ios` job builds it alongside the Android job (working out the release's name by the same rule) and `ios-publish` adds it (and its checksum) once both are done; both keep Kotlin/Native's `~/.konan` in an Actions cache keyed on `libs.versions.toml`; on Linux check with `./gradlew :ios-app:compileKotlinIosArm64`. The iOS player also has More (`IosPlayerMore`: speed in Apple's player, second subtitles via `ApplePlayerSession.setSecondSubtitle` drawn at the top, how it plays from `infoRows`, Media info), chat (`ChatSheet`/`ChatToasts` while this device's group has chat), "Still watching?" (input = taps on Nitrate's buttons plus pauses/jumps seen by `ApplePlayerSession.onInput`, since Apple's controls take the touches) and episodes rolling on at the end. Downloads: `IosDownloadScheduler` runs `DownloadManager.runQueue` in the app (with a background task's extra minutes; retried while offline; `resume` on opening); `ApplePlayerSession.loadLocal` plays a download from the device (MP4/MOV in Apple's player, other containers in mpv), saving watch state with `recordPlayback`; Wi-Fi only applies on Android. Licence texts are bundled from `core-android/src/main/assets/licenses` by `iosApp/project.yml`. Not on iOS yet: the transfer page (its server is JVM-only), speed in mpv, Android's sound and timing choices.
- `:ass-renderer` – libass (ISC) with FreeType (FTL), HarfBuzz (MIT) and FriBidi (LGPL), built static by `tools/build-libass.sh` into `libassJNI.so` behind a small JNI bridge (`AssRenderer`); without that build it compiles with no native code and reports itself unavailable. core-android `playback/AssSubtitles` (`AssSubtitleView`, `PlayerView.assSubtitles()`) draws ASS/SSA in its own layer inside the player's content frame (video frames untouched); `PlaybackSession.assTrack` gives the whole script plus fonts (the file's attachments, or a download's `assFiles`/`fontFiles`), and Media3's own subtitle view gets nothing for that track. Keep `core/OpenSource` in step.
- `:dovi-converter` – libdovi (quietvoid/dovi_tool's `dolby_vision` crate, MIT; Rust) built static by `tools/build-libdovi.sh` (needs rustup) into `libdoviJNI.so` behind `RpuConverter.toProfile81` (one RPU NAL unit, profile 7 → 8.1); without that build it reports itself unavailable and profile 7 plays as its base layer. Keep `core/OpenSource` (libdovi and the shipped crates) in step.
- `:ffmpeg-decoder` – Media3's FFmpeg audio extension (Apache 2.0 sources; its video renderer is an upstream stub, left out) plus Nitrate's own software video decoder (`dev.nitrate.ffmpeg.FfmpegVideoDecoder`/`FfmpegVideoRenderer`, JNI in `ffmpeg_video_jni.cc`: H.264 incl. 10-bit, MPEG-2, MPEG-4 Part 2, VC-1; frames as 8-bit 4:2:0 drawn into the Surface as YV12; up to 1080p) over FFmpeg built LGPL with only those decoders (DTS, TrueHD, AC-3/E-AC-3, ALAC; ARM only) by `tools/build-ffmpeg.sh`. Without that build it compiles with no native code and reports itself unavailable. Players use audio via `EXTENSION_RENDERER_MODE_ON` and add the video renderer after MediaCodec's (both only when the device has no decoder); `DeviceProbe` counts them (`SOFTWARE_VIDEO_DECODER`, `VideoCodecCaps.softwareTenBit` for Hi10P over 8-bit hardware), and the profile keeps software video to 1080p and progressive (`VideoLimit.progressiveOnly`, `tenBitMaxHeight`), VC-1 MKV-only (`MATROSKA_ONLY_VIDEO`). Never enable GPL or non-free FFmpeg parts; keep `core/OpenSource` (the licences pages) in step with what ships.

## Commands

- Build: `./gradlew assembleDebug` (with DTS/TrueHD decoding: run `tools/build-ffmpeg.sh` first; needs the NDK named in `ffmpeg-decoder/build.gradle.kts`)
- Unit tests: `./gradlew test :core:jvmTest` (Gradle's build cache and up-to-date checks skip modules whose inputs didn't change, so never add `cleanTest`; `--rerun` after a test task forces it). While working, run only the touched module's tests (`./gradlew :tv:testDebugUnitTest --tests '*ScreenshotTest.remote*'`), then the whole set once before committing. Modules build and test side by side (`org.gradle.parallel`).
- CI: `build.yml` tests only what a push changed (`tools/changed-parts.py`: job `android` for the Gradle side, `companion` for the plugin; documentation and the Swift host need neither; the workflows themselves count for both). `release.yml` builds the release at once, side by side with Build, then reads those two jobs' results on the same commit ("Tested already?", waiting if they're still running) and skips their tests when they passed, refuses to release when one failed, and tests a part itself when Build skipped it or never ran (a tag elsewhere). Keep the job names `changes`, `android`, `companion`: release reads them.
- If Maven Central returns 429, retry with `--max-workers=2`.

## Conventions

- Screens use `:core` models (`MediaItem`, `PlaybackPlan`…) and talk to the server only through `MediaServer`. Only `core/jellyfin` knows Jellyfin's API.
- Ids are strings (dashed lowercase UUIDs, as stored in settings and row keys) and times are milliseconds; conversion from Jellyfin's dashless ids and ticks happens in `core/jellyfin/Mappers.kt`.
- Jellyfin JSON is PascalCase (`JellyfinJson` maps camelCase DTO fields). DTOs are internal and hold only fields Nitrate reads. When calling a new endpoint, add it to `tools/trim-openapi.py`, regenerate `core/src/jvmTest/resources/jellyfin-openapi.json`, and exercise it in `JellyfinContractTest`, which checks paths, query parameters, body fields and enum values against the spec.
- TV: use `androidx.tv.material3` components so focus and D-pad behaviour are correct; every interactive element must be reachable and visibly focused with a D-pad. Text entry is `TvTextField`, which only opens the keyboard on OK and gives Up/Down back to the D-pad. TV player controls (`ui/player/PlayerControls.kt`): every button is a `PlayerButton` (alike until focused, then white and larger; play/pause round with its symbol); with the controls hidden, OK or an arrow only brings them back; Back closes the topmost thing (handled as a key by the player's root `onKeyEvent` → `goBack()`, as well as `BackHandler`: left to Compose, an unhandled Back first moves focus out of its group, which made More and Info take two presses; a More Settings page consumes Back itself to go back one step) (pop-up, side panel), then hides the controls (playing or paused), then leaves; closing a pop-up keeps the controls up and returns focus to the button that opened it (`ControlFocus`); sub-pages inside a pop-up go back one step; focus is never left nowhere: whatever had it going away (a banner, Up Next, a pop-up) hands it to `refocus()` (the controls' last button, else the player), a guard puts it back if it's lost with nothing open, and banners never take it from More, Info or a dialog (`CreditSceneBanner(takeFocus)`); Back closes what's open before a banner; buttons not yet usable still show focus (outlined, larger); Info is a panel over the video in place of the controls, sized to the screen and scrolled with ▲▼ (`PlaybackInfoPanel`); the remote's Menu key toggles the controls (and closes More or Info back to them); the More button (or Down from the buttons) opens More: `MoreSheet`, a panel across the bottom with the video above, tabs (◀▶; a tab shows when focused; opens on the tab used last) and one tab's `CardRow` or list below, built by `moreTabs`: the season's episodes (wrapping round, "Now" on the one playing, stills blur by `spoilerStill`, watched/progress marks per `DisplayPrefs`; OK plays through `onPlayNext`) or the films of the collection (`NextInCollection.saga`), Chapters (numbered placeholder without a picture), Cast (only with `DisplayPrefs.cast`; OK opens `PersonDialog` over the video: photo, role, born, biography scrolled with Up/Down, "Also in your library"), Extras (`MediaServer.extras`, the show's for an episode; OK plays on top via `onPlayExtra`, and Back/its end returns to the same spot through the entry's saved `resumeAt`; not in a SyncPlay group) and Settings (`PlayerChoicesTab` from `rememberPlayerChoices`: speed, sound, sleep timer, subtitle timing, audio sync, refresh rate (a per-playback `FrameRateMatch` for `FrameRateMatcher`, with `refreshNote` on how the video looks at the TV's rate now), each default from the device's own settings tagged DEFAULT; changes are for this playback, "Make default" saves them; Speakers, Second subtitles, Find subtitles and Watch together as pages that Back leaves: a page takes focus as it opens, and Back returns it to the chip that opened it, the list's `focusRestorer` held off meanwhile); not in easy mode.
- Images: both apps' Coil loader keeps a 512 MB disk cache; cards ask for small art (`backdropUrl(item, maxWidth)`), only full-screen views take 1920px, and the full-screen Home preloads the pictures one press away. Row pages prefetch into the disk cache (each app's `ImagePrefetch`): `PrefetchAlongRow` for the next cards in a row, `PrefetchRows` for the first cards of the rows below; prefetch the exact address the card uses (`rowCardImage(s)`), so a new row style or image size must update those too.
- Dependency versions live in `gradle/libs.versions.toml`.
- Rows (`core/rows/MediaRow`) have a stable `key` such as `home/next_up` or `library/<id>/recently_added`. Display settings are saved against it, so never rename a key.
- TV home and library pages both render through `ui/rows/RowsPage`; add row behaviour there, not per screen. TV Home is `FullArtPage` (one title full screen; ◀▶ items, ▲▼ rows, or with `DisplayPrefs.tvUpDownAlong` / `PageLook.upDownAlong` ("Up/Down: Along the row, then rows", off by default, in Customize's layout and Display → Layout for every page) ▲▼ step items too, going to the next row's first title or the previous row's last only past the ends) or `RowsPage`, chosen by `DisplayPrefs.tvArrangement` (core `PageArrangement`: Full art / Rows one at a time / Stacked rows, one choice; stored under the old name `tvHome`, the old separate stacked switch dropped, so stacked pages saved that way read as Rows one at a time); every top-level page (Home, libraries, custom pages) wraps itself in `MainMenu(currentStopId)`, which shows `TvMenu` from the nav host's `LocalMenuCatalog` (libraries via `rememberLibraries` over core-android `LibraryCache`, which the phone's Libraries tab also uses) in the user's `DisplayPrefs.tvMenu` placement (left/right rail; Top/Bottom bar, at the top on the first row and the bottom on the last, as reported through `LocalMenuRows`; cardinal-only dial rings) with `tvMenuAutoHide` ("Fade in") for any of them and `tvMenuBlack` ("Black menu": rail, bar and dial on solid black) (the old `FADE` style reads as Top/Bottom + fade); reached by moving off the page's edge via `LocalMenuEdge` or the Menu key, never by taking over Back; focus leaving any page towards the menu is redirected to it (`TvMenu`'s page `focusProperties { exit }` → `toMenu`), so it always lands on a stop; with Fade in the menu always lays over the page (never a blank strip of its own). Library pages are laid out like Home unless `DisplayPrefs.tvLibraryArrangement` (stored as `tvLibraryLayout`) says otherwise (full art with the tabs top right via `FullArtPage(header)`, the menu over it); switching tabs (and opening the page) keeps focus on the chosen tab; a library's tabs are core `pages/LibraryTabs` (`LibraryTab`/`LibraryTabKind`: Recommended, All, Genres, Collections, Unwatched, Studios, Decades and the user's own; `resolve` keeps the saved order and adds kinds it doesn't mention, `shown` always leaves one), saved per library with `DisplaySettingsStore.libraryTabs`, arranged in Settings → Display → Pages (`PageSetupScreen` lists Home and each library; both open the same frame, `SetupPage`: Theme first (`ThemeItem`, takes focus once, after it's built), then Tabs with the same `TabActions` (show/hide, rows, move, rename, remove) and "Add your own tab": `HomeSetupScreen` (Home always shows, its rows via `PageEditor`; then the user's custom pages, switch = pinned) and `LibraryTabsScreen`), never on the page; row tabs are `RowsViewModel` pages keyed by `LibraryTabs.pageKey` (Recommended keeps `PageKeys.library`), Genres/Studios/Decades rows from `LibraryTabs.rows` (`MediaServer.studios` = `Studios?parentId`), Unwatched is `BrowseLibrary(viewKey, startWith)`; Fast-forward/Rewind on a row (and in the Edit page's list and row menu, which also has an "Artwork style" line) step its `RowStyle` (`step`), named for a moment (focus waits on a holder in the row while its cards are swapped, then goes into the new style, asked again until a card has it, since some styles lay out a beat later; quick presses step on from the look asked for (`pendingLook`), not the saved one, and only that look takes focus; a guard hands focus back after 10 s if the look never arrives (a slow save is waited for); and the whole row is brought back into view); the All view's A–Z bar goes where `DisplayPrefs.tvLetterBar` says (`LetterBarPlace`: Automatic = the side away from the rail, left, right, top, off). Its stops are `core/pages/MenuStops` ids arranged by the user (`tvMenuStops`, `tvDialStops` with `ring * 4 + spoke` slots; Settings always stays) in `MenuStopsScreen`, built into entries by `menuCatalog`; settings, tools and sign-out sit in `SettingsHubScreen`. Dialogs opened by a long press use `ignoreHeldSelect()` so the held OK button doesn't click their first option. TV art rows draw at a design size and shrink with `designScale` by `RowSize`. Play on a show or season card plays an episode (core `playback/PlayTargets`: a show its `nextUpFor`, else its first season's first unwatched; a season its first unwatched, else its first), resolved before the guards in TV `PlaybackGate.play` and the phone's `guarded`.
- "Because you watched" is kept light for the server: its seeds come from `lastWatchedSeeds` (8 titles, no total count, no pictures), the costly "similar" search is asked for two seeds at a time and for more only when a row came up short (`BecauseYouWatched.rows`), and the rows are kept on the device a day (`BECAUSE_TTL_MS`), their cards' watched marks read afresh each time they're shown from there (`withFreshUserData`: one `Items?ids` request, no pictures); hiding both rows stops it altogether. Other pages can show it as an app row (`AppRows`), sharing Home's answer; and things that read Home's rows in the background use `MediaServer.watchingRows(latest)` (Continue Watching, Next Up and, when asked, each "Latest in…": the TV screensaver and home-screen channels, the phone widgets), never the whole page. Details pages ask for similar titles only while "More like this" shows (`DetailsViewModel(wantsSimilar)` from `DisplayPrefs.similar`).
- Hidden rows are off, not just out of sight: `RowsViewModel(loadProgressSkipping)` passes the saved layout's hidden built-in keys to `MediaServer.homeRowsProgress(skip)`/`libraryRowsProgress(library, skip)` (and `LibraryTabs.rows(skip)` for Genres/Studios/Decades), whose jobs carry the one row key they make (`RowJob.key`) so a hidden one never runs (Home's "Latest in…" per library too; a job making several fixed rows, `RowJob.making(name, keys)`, runs unless all are hidden: "Because you watched", `BecauseYouWatched.slots()`); `RowsProgress.skipped` gives their titles to the editor; hidden custom rows aren't queried either; showing one again reloads the page. Continue Watching and Next Up as one row (`DisplayPrefs.combineContinueNextUp`, off by default, What's shown on both apps): core `rows/ContinueAndNext` (`KEY` `home/continue_and_next`: part way first, then next episodes of shows not already in it), built by `homeRowsProgress(skip, combineContinueNextUp)` via app-core `homeRowsLoader`; the two separate rows keep their keys (widgets, TV channels and the screensaver use `homeRows()`, which still makes them); each Home reloads when the choice changes.
- TV update offer (`components/UpdateDialog`, at app start and from Settings → Updates): "What's new" sits in `ReleaseNotes`, a box of its own height that rolls slowly through the notes by itself until ▲▼ take over (Up from Update now goes straight to it), so the choices always stay on screen.
- Self-update: `core/update/Releases` reads the GitHub releases API (channel from the app id: `.dev` → dev pre-releases, `.debug` → none; version code from the `nitrate-version-code` marker in the notes, else `dev-N` → 1000+N; "What's new" = the notes' list items, written by `release.yml`). `core-android/update/AppUpdater` (`AppContainer.updater`) downloads, verifies against `SHA256SUMS` and installs through `PackageInstaller`; each app shows `UpdatePrompt`. Keep the asset names `nitrate-<mobile|tv>-<name>.apk`.
- Other Jellyfin clients (e.g. Wholphin, GPL) may inspire features, but never copy their code.
