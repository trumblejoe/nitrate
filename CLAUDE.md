# Nitrate

Jellyfin client for Android TV, Android phones/tablets, and (later) iOS. Kotlin (Multiplatform core), Compose, Media3, Ktor.

## Modules

- `:core` – Kotlin Multiplatform (jvm, iosArm64, iosSimulatorArm64). Nitrate's own models (`model/`), the `MediaServer` interface, the Jellyfin client (`jellyfin/`, Ktor + kotlinx.serialization), and all platform-neutral logic: rows, playback rules and test advisor, episode order, Fountain/.fadein, plugin logic. Code lives in `commonMain`; only the transfer server is in `jvmMain`. No `java.*`/`android.*` in `commonMain` — `./gradlew :core:compileKotlinIosArm64` catches it on Linux.
- `:core-android` – Android side of `:core`: OkHttp engine and device identity for `JellyfinClient`, DataStore stores, `DeviceProbe`, `PlaybackSession`, `SettingsSync`, `WritingStore`, and the shared `AppContainer`.
- `:tv` – Android TV app (Compose for TV).
- `:mobile` – Android phone/tablet app (Material 3), written only against `:core` and `:core-android`'s container so it can move to Compose Multiplatform.
- `:ffmpeg-decoder` – Media3's FFmpeg audio extension (Apache 2.0 sources, video renderer left out) over FFmpeg built LGPL and audio-only (DTS, TrueHD, AC-3/E-AC-3, ALAC; ARM only) by `tools/build-ffmpeg.sh`. Without that build it compiles with no native code and reports itself unavailable. Players use it via `EXTENSION_RENDERER_MODE_ON` (only when the device has no decoder); `DeviceProbe` counts it as an audio decoder. Never enable GPL or non-free FFmpeg parts; keep `core/OpenSource` (the licences pages) in step with what ships.

## Commands

- Build: `./gradlew assembleDebug` (with DTS/TrueHD decoding: run `tools/build-ffmpeg.sh` first; needs the NDK named in `ffmpeg-decoder/build.gradle.kts`)
- Unit tests: `./gradlew test`
- If Maven Central returns 429, retry with `--max-workers=2`.

## Conventions

- Screens use `:core` models (`MediaItem`, `PlaybackPlan`…) and talk to the server only through `MediaServer`. Only `core/jellyfin` knows Jellyfin's API.
- Ids are strings (dashed lowercase UUIDs, as stored in settings and row keys) and times are milliseconds; conversion from Jellyfin's dashless ids and ticks happens in `core/jellyfin/Mappers.kt`.
- Jellyfin JSON is PascalCase (`JellyfinJson` maps camelCase DTO fields). DTOs are internal and hold only fields Nitrate reads. When calling a new endpoint, add it to `tools/trim-openapi.py`, regenerate `core/src/jvmTest/resources/jellyfin-openapi.json`, and exercise it in `JellyfinContractTest`, which checks paths, query parameters, body fields and enum values against the spec.
- TV: use `androidx.tv.material3` components so focus and D-pad behaviour are correct; every interactive element must be reachable and visibly focused with a D-pad. Text entry is `TvTextField`, which only opens the keyboard on OK and gives Up/Down back to the D-pad.
- Images: both apps' Coil loader keeps a 512 MB disk cache; cards ask for small art (`backdropUrl(item, maxWidth)`), only full-screen views take 1920px, and the full-screen Home preloads the pictures one press away.
- Dependency versions live in `gradle/libs.versions.toml`.
- Rows (`core/rows/MediaRow`) have a stable `key` such as `home/next_up` or `library/<id>/recently_added`. Display settings are saved against it, so never rename a key.
- TV home and library pages both render through `ui/rows/RowsPage`; add row behaviour there, not per screen. TV Home is `FullArtPage` (one title full screen; ◀▶ items, ▲▼ rows) or `RowsPage`, chosen by `DisplayPrefs.tvHome`; every top-level page (Home, libraries, custom pages) wraps itself in `MainMenu(currentStopId)`, which shows `TvMenu` from the nav host's `LocalMenuCatalog` (libraries via `rememberLibraries` over core-android `LibraryCache`, which the phone's Libraries tab also uses) in the user's `DisplayPrefs.tvMenu` placement (left/right rail; Top/Bottom bar, at the top on the first row and the bottom on the last, as reported through `LocalMenuRows`; cardinal-only dial rings) with `tvMenuAutoHide` ("Fade in") for any of them (the old `FADE` style reads as Top/Bottom + fade); reached by moving off the page's edge via `LocalMenuEdge` or the Menu key, never by taking over Back. Its stops are `core/pages/MenuStops` ids arranged by the user (`tvMenuStops`, `tvDialStops` with `ring * 4 + spoke` slots; Settings always stays) in `MenuStopsScreen`, built into entries by `menuCatalog`; settings, tools and sign-out sit in `SettingsHubScreen`. Dialogs opened by a long press use `ignoreHeldSelect()` so the held OK button doesn't click their first option. TV art rows draw at a design size and shrink with `designScale` by `RowSize`.
- Pages (Home `PageKeys.HOME`, library overviews `PageKeys.library(id)`, custom pages `PageKeys.custom(id)`) are assembled by `RowsViewModel` from built-in rows plus the user's `PageLayout` (core `pages/`): order, hidden, renamed and custom rows (`RowSource` query/collection/playlist). Layouts, custom pages and `DisplayPrefs` live in `DisplaySettingsStore` and sync like other display settings. Anything shown about an item (ratings, overview, badges, titles, progress...) must respect `DisplayPrefs` via each app's `LocalDisplayPrefs`; use `DisplayPrefs.facts(item)` for fact lines.
- Admin calls live in `core/jellyfin/JellyfinAdmin.kt`. Item updates and user policies round-trip the server's own JSON (never rebuild them from DTOs) and drop read-only parts first (`READ_ONLY_ITEM_FIELDS`; 12.4 can't parse its own `Trickplay` back). Admin UI shows only when `AppContainer.account` says `isAdmin`.
- Shared test fixtures (`FakeServer`, sample art) live in `testing/` and are on both apps' test source paths.
- Playback capability ids are a codec name (`hevc`, `eac3`) or `range:<HDR format>`. Playback settings are per device and must never be synced; display settings are per user and sync through `SettingsSync`. Per-series language choices (`TrackMemoryStore`) are display settings and sync; night mode, subtitle style, PiP and background audio are playback settings.
- Device backups: each device's own settings (playback + plugins, `core/backup/DeviceSettings`; never PINs/profile choices, scripts have their own backup) are saved by core-android `backup/DeviceBackupManager` (`AppContainer.backups`) to the user's Jellyfin display preferences (`nitrate-device-<deviceId>`, listed in `nitrate-devices`; each device writes only its own) a few seconds after any change, but only once the account is "settled": after first sign-in a device with other backups asks "Set this device up like…" (`offer`, each app's `BackupPrompt`) and nothing is pushed until it's answered ("Not now" keeps a reinstalled device's old backup as "(earlier)"). Restores always show `DeviceBackups.differences` first and apply only on confirm; hardware results (overrides, learned failures, height limits, 8/10-bit) carry over only from the same model (`DeviceBackups.restored`). Settings → Device backup on both apps; the phone also exports/imports a file.
- Remote control: `AppContainer.remote` (`RemoteControlHub`) listens to `MediaServer.events()` and forwards commands to the player that registered itself as `remote.active`; each app handles `Play`/`DisplayMessage`/volume itself.
- SyncPlay: the logic is `core/syncplay/SyncPlayController` (clock, commands, ready/buffering, drift), fed by `RemoteControlHub` and shared as `AppContainer.syncPlay`. `PlaybackSession.followGroup` makes its public `player` (a `ForwardingPlayer`) turn play/pause/seek into group requests while in a group; the group's commands act on the session's private ExoPlayer. Apps open a player for `syncPlay.openRequests`.
- Accounts: `SessionStorage` keeps every signed-in server/user (`StoredSession.key` = "serverUrl|userId") and which is current; `MediaServer.switchAccount`/`forgetAccount`/`savedAccounts`. Apps switch through `AppContainer.switchAccount`/`signOut` (they leave SyncPlay and restart the live connection) and route with `shouldPickProfile`. Profile PINs and "ask who's watching" are device-only (`ProfileStore`), never synced. All accounts share one device id (Jellyfin 12.4 keeps each user's token). Servers: every account on a server keeps the same `localUrl`/`vpnUrl`/`remoteUrl` (plus `serverId` and `primary`), set together via `SessionStorage.update` (in place, current unchanged). `JellyfinClient.reconnect()` probes local → VPN → remote → signed-in address (local with a short timeout), only ever for the same server id; `restoreSession` starts on the primary server; `AppContainer` reconnects on network changes (restarting the live connection if the address moved). `serverUrl` stays the address signed in with, so the account key never changes. `MediaServer.servers()`/`saveServerAddresses`/`setPrimaryServer`/`testAddress` back each app's Servers screen.
- New-episode notifications: which episodes to announce is `core/notifications/NewEpisodes`; `AppContainer.newEpisodes` (`NewEpisodeNotifier`) checks via WorkManager and on `LibraryChanged`, remembering the newest add seen per account. Taps reach `MainActivity` with `NewEpisodeNotifier.EXTRA_OPEN_ITEM`.
- Library browsing ("All"): `core/pages/Browse.kt` (`BrowseOptions` → `ItemQuery`, A–Z via `Browse.before` counts) and `BrowseViewModel`; options are saved with `DisplaySettingsStore.saveView` under `browse/<libraryId>`. Codec, bit-depth and dynamic-range filters (`ItemQuery.videoCodecs`/`bitDepths`/`videoRanges`/`audioCodecs`, `core/pages/Codecs`; video choices must all hold on one video stream, Dolby Vision also counts as its base layer) are applied by Nitrate because Jellyfin can't: `JellyfinClient` builds a per-library codec index from `fields=MediaStreams` (shows from their episodes; Jellyfin answers from its database, never the media files), cached 15 minutes, and pages the server's id list through it. Playlist libraries keep their own tile grid.
- Lists: playlists and collections are edited through `MediaServer` (`createPlaylist`, `addToPlaylist`, `movePlaylistItem`... by `MediaItem.playlistEntryId`; `createCollection`... needs `AccountInfo.canManageCollections`). Each app has an `AddToListDialog`.
- TV home screen: `core/rows/HomeChannelContent` decides Play Next vs. channel items from Home rows; `tv/channels/HomeChannels` writes them with androidx.tvprovider (WorkManager + after playback) and links back with `nitrate://item|play/<id>` (`TvLinks`). `MainActivity` turns links, ACTION_SEARCH and the search key into `TvRequest`s that `NitrateNavHost` carries out once signed in.
- Music: `MediaServer.albumTracks`/`artistAlbums`/`albumArtists`/`instantMix`; tracks carry `album`/`albumId`/`artists` and fall back to the album cover. Players show the cover via `PlayerView.showCover` (Media3 only shows embedded art).
- Live TV: models and guide layout in `core/livetv` (`LiveChannel`, `TvProgram`, `Guide.cells`); Jellyfin calls in `core/jellyfin/JellyfinLiveTv.kt` (recording uses the server's own `Timers/Defaults` JSON); `LiveTvViewModel` shared; channels are `ItemKind.TV_CHANNEL` and play like any item.
- Pages reload on server pushes: pass `AppContainer.serverChanges` to `RowsViewModel`.
- Plugins are compiled in (no downloaded code). Logic lives in `:core` (`NitratePlugin`, `PlaybackGuard`) and is registered in `AppContainer.plugins`; each app adds its screens for a plugin by `pluginId` (TV: `TV_PLUGIN_UI`). A plugin's `id` is a storage key: never change it.
- Downloads: logic in `core/downloads` (`DownloadManager`, common Kotlin with kotlinx-io); Android runs it through WorkManager (`core-android/downloads`), UI in `:mobile` only. A downloaded item plays from the device (`PlayerRoute(local = true)`) and its watch state is recorded locally and sent by `syncWatchState`, never through `/Sessions` reporting. Transcoded downloads need a fresh `playSessionId` each time or the server reuses an old transcode. Jellyfin 12.4 rejects `api_key` query auth: always send the Authorization header.
- Mobile look: screens sit in `TintedBackdrop` (tint from `rememberArtworkColor`), use `accentColor()` for highlights, `SectionHeader`, `PillButton`, `RoundAction`, and `pressable()` for touch feedback. Artwork that should morph into the page it opens gets a `sharedKey`/`sharedArtwork(key)` unique on its screen, passed on as `DetailsRoute.artKey`. Leave `NavBarClearance` at the bottom of tab screens for the floating nav pill. Rows render through `CinematicRow` (Posters/Artwork/Showcase/Film strip/Lightning split/Cressida, chosen from the row header via `onDisplay`; the last three live in `ArtRows.kt` in each app and share geometry from core `RowArt` and drawing from core-android `art/RowArtDrawing`; Cressida's linework is `RowDisplay.ink` (`CressidaInk`) coloured by `inkTint`/`inkArgb` (Smart = core `InkPalette.smart` over the card's artwork pixels, via each app's `rememberInkColor`), drawn procedurally and deterministically there — keep designs original, no copied emblems or logos); the phone's Home passes `ArtworkFirst::display` as `RowsViewModel` defaults, so unstyled rows show artwork rather than posters. Screenshot tests use the abstract art from `tools/generate-sample-art.py`.
- Playback reports: core `playback/PlaybackReport` renders device caps, what Nitrate allows, the item's streams, the server's decision and `PlaybackSession.eventLog()` (last 300 player events) as text, with tokens stripped from URLs; `AppContainer.sendPlaybackReport` saves it on the user's Jellyfin as a client log (`POST /ClientLog/Document`, shown under Dashboard → Logs). TV: player Send log and Playback settings → Send device report; phone: player Info → Send log / Share and Settings → Send device report.
- Every single-item "play" goes through `PluginRegistry.checkBeforePlay` (TV: `PlaybackGate`) so guards run; queued playback (playlists) deliberately bypasses it.
- Self-update: `core/update/Releases` reads the GitHub releases API (channel from the app id: `.dev` → dev pre-releases, `.debug` → none; version code from the `nitrate-version-code` marker in the notes, else `dev-N` → 1000+N; "What's new" = the notes' list items, written by `release.yml`). `core-android/update/AppUpdater` (`AppContainer.updater`) downloads, verifies against `SHA256SUMS` and installs through `PackageInstaller`; each app shows `UpdatePrompt`. Keep the asset names `nitrate-<mobile|tv>-<name>.apk`.
- Other Jellyfin clients (e.g. Wholphin, GPL) may inspire features, but never copy their code.
