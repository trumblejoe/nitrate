# Nitrate

Jellyfin client for Android TV, Android phones/tablets, and (later) iOS. Kotlin (Multiplatform core), Compose, Media3, Ktor.

## Modules

- `:core` – Kotlin Multiplatform (jvm, iosArm64, iosSimulatorArm64). Nitrate's own models (`model/`), the `MediaServer` interface, the Jellyfin client (`jellyfin/`, Ktor + kotlinx.serialization), and all platform-neutral logic: rows, playback rules and test advisor, episode order, Fountain/.fadein, plugin logic. Code lives in `commonMain`; only the transfer server is in `jvmMain`. No `java.*`/`android.*` in `commonMain` — `./gradlew :core:compileKotlinIosArm64` catches it on Linux.
- `:core-android` – Android side of `:core`: OkHttp engine and device identity for `JellyfinClient`, DataStore stores, `DeviceProbe`, `PlaybackSession`, `SettingsSync`, `WritingStore`, and the shared `AppContainer`.
- `:tv` – Android TV app (Compose for TV).
- `:mobile` – Android phone/tablet app (Material 3), written only against `:core` and `:core-android`'s container so it can move to Compose Multiplatform.
- `companion/` – Nitrate Companion, a Jellyfin server plugin (C#, .NET 10, against Jellyfin 12.4's NuGet packages; GPL-3.0 because it builds on Jellyfin's libraries) for what Jellyfin has no API for: chat in SyncPlay groups (`/Nitrate/Chat`, long polling), single sign-on (`/Nitrate/Sso`, open), household channels (`/Nitrate/Channels`), watch partners and private accounts (`/Nitrate/Partners`, `/Nitrate/Privacy`) and shared screenplays (`/Nitrate/Scripts`: owner + invited members, compare-and-set edits on the latest version, long-polled edits and cursors, kept in the server's data folder). Apps find it with `GET /Nitrate/Companion` and hide features without it. Released as `nitrate-companion-<v>.zip` plus a plugin-repository manifest on the `companion-repo` release (`tools/companion-manifest.py`). Its plugin id is a storage key: never change it. Test with `dotnet test companion/Nitrate.Companion.Tests`.
- `:ffmpeg-decoder` – Media3's FFmpeg audio extension (Apache 2.0 sources, video renderer left out) over FFmpeg built LGPL and audio-only (DTS, TrueHD, AC-3/E-AC-3, ALAC; ARM only) by `tools/build-ffmpeg.sh`. Without that build it compiles with no native code and reports itself unavailable. Players use it via `EXTENSION_RENDERER_MODE_ON` (only when the device has no decoder); `DeviceProbe` counts it as an audio decoder. Never enable GPL or non-free FFmpeg parts; keep `core/OpenSource` (the licences pages) in step with what ships.

## Commands

- Build: `./gradlew assembleDebug` (with DTS/TrueHD decoding: run `tools/build-ffmpeg.sh` first; needs the NDK named in `ffmpeg-decoder/build.gradle.kts`)
- Unit tests: `./gradlew test`
- If Maven Central returns 429, retry with `--max-workers=2`.

## Conventions

- Screens use `:core` models (`MediaItem`, `PlaybackPlan`…) and talk to the server only through `MediaServer`. Only `core/jellyfin` knows Jellyfin's API.
- Ids are strings (dashed lowercase UUIDs, as stored in settings and row keys) and times are milliseconds; conversion from Jellyfin's dashless ids and ticks happens in `core/jellyfin/Mappers.kt`.
- Jellyfin JSON is PascalCase (`JellyfinJson` maps camelCase DTO fields). DTOs are internal and hold only fields Nitrate reads. When calling a new endpoint, add it to `tools/trim-openapi.py`, regenerate `core/src/jvmTest/resources/jellyfin-openapi.json`, and exercise it in `JellyfinContractTest`, which checks paths, query parameters, body fields and enum values against the spec.
- TV: use `androidx.tv.material3` components so focus and D-pad behaviour are correct; every interactive element must be reachable and visibly focused with a D-pad. Text entry is `TvTextField`, which only opens the keyboard on OK and gives Up/Down back to the D-pad.
- Images: both apps' Coil loader keeps a 512 MB disk cache; cards ask for small art (`backdropUrl(item, maxWidth)`), only full-screen views take 1920px, and the full-screen Home preloads the pictures one press away. Row pages prefetch into the disk cache (each app's `ImagePrefetch`): `PrefetchAlongRow` for the next cards in a row, `PrefetchRows` for the first cards of the rows below; prefetch the exact address the card uses (`rowCardImage(s)`), so a new row style or image size must update those too.
- Dependency versions live in `gradle/libs.versions.toml`.
- Rows (`core/rows/MediaRow`) have a stable `key` such as `home/next_up` or `library/<id>/recently_added`. Display settings are saved against it, so never rename a key.
- TV home and library pages both render through `ui/rows/RowsPage`; add row behaviour there, not per screen. TV Home is `FullArtPage` (one title full screen; ◀▶ items, ▲▼ rows) or `RowsPage`, chosen by `DisplayPrefs.tvHome`; every top-level page (Home, libraries, custom pages) wraps itself in `MainMenu(currentStopId)`, which shows `TvMenu` from the nav host's `LocalMenuCatalog` (libraries via `rememberLibraries` over core-android `LibraryCache`, which the phone's Libraries tab also uses) in the user's `DisplayPrefs.tvMenu` placement (left/right rail; Top/Bottom bar, at the top on the first row and the bottom on the last, as reported through `LocalMenuRows`; cardinal-only dial rings) with `tvMenuAutoHide` ("Fade in") for any of them (the old `FADE` style reads as Top/Bottom + fade); reached by moving off the page's edge via `LocalMenuEdge` or the Menu key, never by taking over Back. Its stops are `core/pages/MenuStops` ids arranged by the user (`tvMenuStops`, `tvDialStops` with `ring * 4 + spoke` slots; Settings always stays) in `MenuStopsScreen`, built into entries by `menuCatalog`; settings, tools and sign-out sit in `SettingsHubScreen`. Dialogs opened by a long press use `ignoreHeldSelect()` so the held OK button doesn't click their first option. TV art rows draw at a design size and shrink with `designScale` by `RowSize`.
- Pages (Home `PageKeys.HOME`, library overviews `PageKeys.library(id)`, custom pages `PageKeys.custom(id)`) are assembled by `RowsViewModel` from built-in rows plus the user's `PageLayout` (core `pages/`): order, hidden, renamed and custom rows (`RowSource` query/collection/playlist). Layouts, custom pages and `DisplayPrefs` live in `DisplaySettingsStore` (in the device's display profile, see below) and sync like other display settings. Spoiler hiding: `isSpoiler` blurs unwatched episodes' stills; `hidesDescription` holds back descriptions of unwatched episodes and movies (details pages offer "Show"). Anything shown about an item (ratings, overview, badges, titles, progress...) must respect `DisplayPrefs` via each app's `LocalDisplayPrefs`; use `DisplayPrefs.facts(item)` for fact lines.
- Metadata locks and bulk editing (admins): field locks are core `admin/LockableField` (Jellyfin's `MetadataField` names only; `saveMetadata` drops anything else, since an unknown name makes the server refuse the save), toggled by the lock icons/chips in each app's Manage → Details. `admin/BulkEdit` (add/remove genres, tags, studios; set/clear age rating; lock/unlock fields or the whole item) reads, changes and saves each title's own metadata (`run` reports changed/unchanged/failed); each app's library "All" view has an admin "Select to edit" mode → edit, review (`describe`), apply, results (`BrowseViewModel.reload` after). Manage → Details also shows the title's theme music (`MediaServer.themeMusicInfo`: own or the series', with a preview).
- Admin calls live in `core/jellyfin/JellyfinAdmin.kt`. Item updates and user policies round-trip the server's own JSON (never rebuild them from DTOs) and drop read-only parts first (`READ_ONLY_ITEM_FIELDS`; 12.4 can't parse its own `Trickplay` back). Admin UI shows only when `AppContainer.account` says `isAdmin`.
- Shared test fixtures (`FakeServer`, sample art) live in `testing/` and are on both apps' test source paths.
- Playback capability ids are a codec name (`hevc`, `eac3`) or `range:<HDR format>`. Playback settings are per device and must never be synced; display settings are per user and sync through `SettingsSync`. Per-series language choices (`TrackMemoryStore`) are display settings and sync, and hold only the kind of track the user picked (audio or subtitles; `TrackMemory.VERSION`) so the rest follows the server account's language settings, which Jellyfin applies through PlaybackInfo's default stream indices; night mode, subtitle style, PiP and background audio are playback settings.
- Display profiles (core `pages/DisplayProfiles`): display settings live in profiles; each device's choice of profile is device-only (`DisplaySettingsStore.useProfile`, stored outside the synced map). Profile entries are stored as `p:<profile>:<name>`; shared on every device (`DisplayProfiles.isShared`): custom pages and their layouts (`layout:custom/...`), per-series languages (`tracks`), the profile list and `shared` (spoiler hiding, read over `DisplayPrefs.hideSpoilers`). Built-in profiles TV/Phone/Tablet (`DeviceKind`, chosen by `AppContainer.deviceKind`) are never written: choosing one asks for a name and creates a profile; a change made while on one forks a profile named after the device. Settings saved before profiles migrate to "My settings" (`migrated`). `SettingsSync` keeps everything under display-preferences id `nitrate-display` (older versions still write the single set under `nitrate`, only read once to seed) and merges per entry against the last agreed copy (`DisplayProfiles.merge`) so devices never undo each other. TV: Settings → Display profile, including importing only another profile's radial menu (differences first).
- Device backups: each device's own settings (playback + plugins, `core/backup/DeviceSettings`; never PINs/profile choices, scripts have their own backup) are saved by core-android `backup/DeviceBackupManager` (`AppContainer.backups`) to the user's Jellyfin display preferences (`nitrate-device-<deviceId>`, listed in `nitrate-devices`; each device writes only its own) a few seconds after any change, but only once the account is "settled": after first sign-in a device with other backups asks "Set this device up like…" (`offer`, each app's `BackupPrompt`) and nothing is pushed until it's answered ("Not now" keeps a reinstalled device's old backup as "(earlier)"). Restores always show `DeviceBackups.differences` first and apply only on confirm; hardware results (overrides, learned failures, height limits, 8/10-bit) carry over only from the same model (`DeviceBackups.restored`). Settings → Device backup on both apps; the phone also exports/imports a file.
- Remote control: `AppContainer.remote` (`RemoteControlHub`) listens to `MediaServer.events()` and forwards commands to the player that registered itself as `remote.active`; each app handles `Play`/`DisplayMessage`/volume itself.
- SyncPlay: the logic is `core/syncplay/SyncPlayController` (clock, commands, ready/buffering, drift), fed by `RemoteControlHub` and shared as `AppContainer.syncPlay`. `PlaybackSession.followGroup` makes its public `player` (a `ForwardingPlayer`) turn play/pause/seek into group requests while in a group; the group's commands act on the session's private ExoPlayer. Apps open a player for `syncPlay.openRequests`.
- Watch-together chat (needs the Companion plugin): `MediaServer.companion`/`chatMessages`/`sendChat` (core `jellyfin/JellyfinCompanion.kt`, outside the OpenAPI contract test); core `companion/GroupChat` long-polls one group, keeps its messages and emits `incoming` from others; `AppContainer.chat` follows this device's SyncPlay group, or `chatAlongside(groupId)` for a phone chatting beside the TV without playing (allowed for any of the user's devices in the group). Apps: pop-ups over the video (`ChatToasts`), a chat panel/sheet with `QUICK_REACTIONS` (TV: one press each) and text; TV Watch together page shows the chat beside the group; phone Watch together offers "Chat" on groups the user is already in.
- Shared screenplays (needs the Companion plugin, feature `scripts`): core `writing/TextOperation` (OT: apply/compose/transform/diff, cursor mapping; UTF-16 lengths like C#) and `writing/SharedScriptSession` (keeps the sent-but-unconfirmed change and the typed-since buffer, transforms both over others' edits, resends after a refusal, offline/restart-safe via `SharedScriptState`, reloads and keeps a copy if too far behind; single-threaded: run it on the UI scope). core-android `writing/SharedWriting` (`AppContainer.sharedWriting`) links a local script to a shared one per account (`WritingStore.saveLink`/`link`, `WritingDoc.sharedId`), so every shared script is also the user's own script and in their own backups; leaving, being removed or the owner stopping keeps it as theirs. Only the owner and invited people can open one. Editors route every text change through `session.edit`, apply `session.remote` with the selection moved by the op, mark `others`' cursors in the highlight; Share/Sharing (TV panel, phone dialog) and "Shared with you" in the documents list.
- Script ownership and sync: each script belongs to the account that made it (`WritingStore` owners; `docs` lists only the signed-in account's; scripts from before owners go to the first signed-in account; a backup never takes another account's script). With the Companion plugin, `SharedWriting.autoSync` (after sign-in, a few seconds after scripts are added/linked, every 5 minutes) puts this account's scripts on its server as private shared scripts (sharing = inviting members; "stop sharing" keeps it synced) and brings in the user's own scripts made elsewhere, but only when the account syncs: per-account device-only choice (`syncOptions`/`setSync`, default on only for the Primary server; a new server never gets scripts until switched on). One home server per script: `move(localId, account)` deletes the server copy and gives the script to another account (synced there when it's in use); `move(localId, null)` keeps it on this device only (`isDeviceOnly`). Unsynced scripts keep their history on the device (`WritingStore.localLog`/`historyStart`, core `story/LocalHistory`, compacted past 20,000 changes; not backed up), so `SharedWriting.history`/`authorship` always work. Labels: `WritingDoc.placeLabel`.
- Script story (lists, scenes, map, comments, history): core `writing/story`. Scenes are the script's headings, each carrying a hidden note `[[scene:id]]` (`Outline`: scenes, `addIds` once the writer leaves the line, `move`/`add` as text changes, `Hidden` maps editor offsets, `stripMarkers` for exports/word counts). `Story` records (list, entry, link, comment, scene details) merge field by field with who/when; Characters/Locations are detected from the script (`listItems`, stable `detectedId`). `StoryGraph` builds/filters/lays out the map (`EdgeKind` colours in `StoryColors`); `Attribution`/`History` give who-wrote-what, activity and restores. Shared scripts carry records in the same edit stream (`SharedScriptSession.changeStory`/`story`); unshared ones keep them in `WritingStore.readStory`/`saveStory` (and their backup). core-android `StoryContext`/`StoryHistory`/`ScriptStory`, `SharedWriting.storyFor`/`log`/`at`/`authorship`/`writers`/`history`. UI: phone editor tabs (`StoryPanels.kt`), TV editor buttons (`StoryTv.kt`; map is view + filter, links made from an entry).
- Single sign-on (Companion feature `sso`; settings on the plugin's dashboard page): the plugin's `Sso/SsoService` runs OpenID Connect (code + PKCE; id token checked against the provider's JWKS with the framework's crypto, no extra libraries) and issues a Jellyfin token through `IDeviceManager.CreateDevice` for existing users only (user name claim, verified email = user name, admin links; optional group). Devices `startSso` → show `SsoRequest.url`/`code` (TV: `QrCode`, ZXing) or open it in the browser (phone) → `pollSso` until `Done`, which signs in like a password would. The browser page asks to confirm the device's code before going to the provider.
- Channels (pseudo-TV; Companion feature `channels` + core `channels/ChannelsPlugin`, on by default): admins make `HouseChannel`s (lineup `ChannelSource`s, `ChannelMix`, `alignMinutes`, `ChannelBlock` time slots, `everyone`/`users` grants). The plugin makes and stores the schedule a few days ahead (`Channels/ChannelScheduler`: per-source cursors, undone by `DropFuture` on edits so shows keep their place), so the guide is the same for everyone; nothing ever streams by itself. Tuning in (`MediaServer.tuneChannel`) gives what's on now and what follows; apps play it as a queue from the start of each (`playQueue`), never mid-program. core-android `ChannelsViewModel`; TV `ui/channels` (menu stop `MenuStops.CHANNELS`, guide grid via `Channels.asTvPrograms` + `Guide.cells`, held OK edits), phone `Channels.kt` (Library tab entry). Calls in `core/jellyfin/JellyfinChannels.kt`, outside the OpenAPI contract test.
- Watch partners (Companion feature `partners` + core `partners/WatchPartnersPlugin`, a `PlaybackGuard`, on by default): watch groups (the plugin's `Partners/PartnerHub`, `WatchGroup`): people who watch one show together and all see each other's progress in it; a pair is a group of two, one show can have several groups, a person can be in many. Any member invites (`askPartner(..., groupId)`; null makes a new group with the inviter); the invitee accepts, first shown exactly who'll learn their name (`IncomingRequest.willSee`); leaving a group of two ends it. Private accounts (admin list `PrivateUserIds` in the plugin settings, or the user's own "Keep me private") are never listed (`/Nitrate/Partners/People`, and the script-sharing `/Nitrate/Users` list and name lookup) or findable; an invite to a typed name always reads "sent" and stays waiting until accepted or lapsed (14 days), declined or not, existing or not — never add anything that tells an inviter whether an account exists. Before an episode of a shared show plays, the guard asks if someone in a group hasn't seen it, one choice per group ("Watching with Will", "Watching with Frank, Tommy and Jane") or "Just me" (`GuardAction.RunThenPlay` starts a core `TogetherSession` for that group, 8 h); `AppContainer.watchPartners.settle` (on `UserDataChanged` and after leaving a player) marks episodes the user newly finished as watched for the rest of that group (`watchedTogether(itemId, groupId)`, server checks membership and the show). Spoiler hiding on shared shows goes by the furthest-behind member of any of the user's groups (each app's `LocalPartnerProgress`, `spoilerStill`/`descriptionHidden`). Home row `home/up_next_together` (per group). Invites show when the app opens (`PartnerRequestPrompt`, "Later" until next time); Settings → Watch partners; "Watch with…" on a show's page. Calls in `core/jellyfin/JellyfinPartners.kt`.
- "Last time" recaps: core `recap/Recaps` builds a `Recap` before resuming a show's episode (or the next item of a playlist marked in story order, `DisplayPrefs.recapPlaylists`, shared on every device via `SharedPrefs`) when the last watch (`UserState.lastPlayedMs`) is at least `DisplayPrefs.recapAfterDays` ago for shows, `playlistRecapAfterDays` for playlists (0 = never; per display profile): the last few things watched (never anything ahead), where the user is, and a `RecapClip` of the last one's ending before its credits (server OUTRO segment, else a credits-named chapter, else runtime − 1 min; 3 min). `AppContainer.recapBefore` (2.5 s cap, so playing never waits long) sets `pendingRecap`; each app's play path (phone `go` in `MobileApp`, TV `rememberPlaybackGate`) opens `RecapRoute` instead of the player when one is due; marked playlists get "Continue" on their page. Clips play with `PlaybackSession.loadClip` (`PlayerRoute.clipEndMs`): nothing reported to the server (watch history and resume points untouched), no Up Next, never joined to a SyncPlay group, ends at the clip's end.
- Accounts: `SessionStorage` keeps every signed-in server/user (`StoredSession.key` = "serverUrl|userId") and which is current; `MediaServer.switchAccount`/`forgetAccount`/`savedAccounts`. Apps switch through `AppContainer.switchAccount`/`signOut` (they leave SyncPlay and restart the live connection) and route with `shouldPickProfile`. Profile PINs and "ask who's watching" are device-only (`ProfileStore`), never synced. All accounts share one device id (Jellyfin 12.4 keeps each user's token). Servers: every account on a server keeps the same `localUrl`/`vpnUrl`/`remoteUrl` (plus `serverId` and `primary`), set together via `SessionStorage.update` (in place, current unchanged). `JellyfinClient.reconnect()` probes local → VPN → remote → signed-in address (local with a short timeout), only ever for the same server id; `restoreSession` starts on the primary server; `AppContainer` reconnects on network changes (restarting the live connection if the address moved). `serverUrl` stays the address signed in with, so the account key never changes. `MediaServer.servers()`/`saveServerAddresses`/`setPrimaryServer`/`testAddress` back each app's Servers screen.
- New-episode notifications: which episodes to announce is `core/notifications/NewEpisodes`; `AppContainer.newEpisodes` (`NewEpisodeNotifier`) checks via WorkManager and on `LibraryChanged`, remembering the newest add seen per account. Taps reach `MainActivity` with `NewEpisodeNotifier.EXTRA_OPEN_ITEM`.
- Library browsing ("All"): `core/pages/Browse.kt` (`BrowseOptions` → `ItemQuery`, A–Z via `Browse.before` counts) and `BrowseViewModel`; options are saved with `DisplaySettingsStore.saveView` under `browse/<libraryId>`. Codec, bit-depth and dynamic-range filters (`ItemQuery.videoCodecs`/`bitDepths`/`videoRanges`/`audioCodecs`, `core/pages/Codecs`; video choices must all hold on one video stream, Dolby Vision also counts as its base layer) are applied by Nitrate because Jellyfin can't: `JellyfinClient` builds a per-library codec index from `fields=MediaStreams` (shows from their episodes; Jellyfin answers from its database, never the media files), cached 15 minutes, and pages the server's id list through it. Playlist libraries keep their own tile grid.
- Lists: playlists and collections are edited through `MediaServer` (`createPlaylist`, `addToPlaylist`, `movePlaylistItem`... by `MediaItem.playlistEntryId`; `createCollection`... needs `AccountInfo.canManageCollections`). Each app has an `AddToListDialog`: multi-select over both lists at once (TV: two columns; phone: tabs), new lists only created on confirm, always a review step before anything is added; logic in core `lists/AddToLists` (`load` fetches both together, `apply` reports each target).
- TV home screen: `core/rows/HomeChannelContent` decides Play Next vs. channel items from Home rows; `tv/channels/HomeChannels` writes them with androidx.tvprovider (WorkManager + after playback) and links back with `nitrate://item|play/<id>` (`TvLinks`). `MainActivity` turns links, ACTION_SEARCH and the search key into `TvRequest`s that `NitrateNavHost` carries out once signed in.
- Music: `MediaServer.albumTracks`/`artistAlbums`/`albumArtists`/`instantMix`; tracks carry `album`/`albumId`/`artists` and fall back to the album cover. Players show the cover via `PlayerView.showCover` (Media3 only shows embedded art).
- Live TV: models and guide layout in `core/livetv` (`LiveChannel`, `TvProgram`, `Guide.cells`); Jellyfin calls in `core/jellyfin/JellyfinLiveTv.kt` (recording uses the server's own `Timers/Defaults` JSON); `LiveTvViewModel` shared; channels are `ItemKind.TV_CHANNEL` and play like any item.
- Pages reload on server pushes: pass `AppContainer.serverChanges` to `RowsViewModel`. Screens open with what they showed last time from `AppContainer.dataCache` (core-android `DataCache`, per account and key, in the cache folder) while fresh data loads: page rows (`RowsViewModel`), details pages and each season's episodes (`DetailsViewModel`), the Add-to lists; never wait on it and always replace it with fresh data; Home and library pages load progressively: `MediaServer.homeRowsProgress`/`libraryRowsProgress` run each row (or source of rows) as a core `rows/RowJob` through `ProgressiveRows.run`, emitting the rows so far in page order as each answers, and `RowsViewModel(loadProgress = …)` overlays them on what's shown (`ProgressiveRows.overlay`) so no page waits for its slowest row; OkHttp allows 16 requests per server, so keep new rows independent jobs. Nothing network-bound should be awaited before Home appears (`onSignedIn` only launches).
- Plugins are compiled in (no downloaded code). Logic lives in `:core` (`NitratePlugin`, `PlaybackGuard`) and is registered in `AppContainer.plugins`; each app adds its screens for a plugin by `pluginId` (TV: `TV_PLUGIN_UI`). A plugin's `id` is a storage key: never change it.
- Downloads: logic in `core/downloads` (`DownloadManager`, common Kotlin with kotlinx-io); Android runs it through WorkManager (`core-android/downloads`), UI in `:mobile` only. A downloaded item plays from the device (`PlayerRoute(local = true)`) and its watch state is recorded locally and sent by `syncWatchState`, never through `/Sessions` reporting. Transcoded downloads need a fresh `playSessionId` each time or the server reuses an old transcode. Jellyfin 12.4 rejects `api_key` query auth: always send the Authorization header.
- Mobile look: screens sit in `TintedBackdrop` (tint from `rememberArtworkColor`), use `accentColor()` for highlights, `SectionHeader`, `PillButton`, `RoundAction`, and `pressable()` for touch feedback. Artwork that should morph into the page it opens gets a `sharedKey`/`sharedArtwork(key)` unique on its screen, passed on as `DetailsRoute.artKey`. Leave `NavBarClearance` at the bottom of tab screens for the floating nav pill. Rows render through `CinematicRow` (Posters/Artwork/Showcase/Film strip/Lightning split/Cressida, chosen from the row header via `onDisplay`; the last three live in `ArtRows.kt` in each app and share geometry from core `RowArt` and drawing from core-android `art/RowArtDrawing`; Cressida's linework is `RowDisplay.ink` (`CressidaInk`) coloured by `inkTint`/`inkArgb` (Smart = core `InkPalette.smart` over the card's artwork pixels, via each app's `rememberInkColor`), drawn procedurally and deterministically there — keep designs original, no copied emblems or logos); the phone's Home passes `ArtworkFirst::display` as `RowsViewModel` defaults, so unstyled rows show artwork rather than posters. Screenshot tests use the abstract art from `tools/generate-sample-art.py`.
- Phone player swipes (brightness left, volume right) must stay hard to trigger by accident: core `playback/SwipeLevel` decides starts (edges excluded, flicks and sideways moves rule the touch out) and `LevelDrag` the level (rests at 50%); `PlaybackSettings.swipeControls` turns them off.
- Playback reports: core `playback/PlaybackReport` renders device caps, what Nitrate allows, the item's streams, the server's decision and `PlaybackSession.eventLog()` (last 300 player events) as text, with tokens stripped from URLs; `AppContainer.sendPlaybackReport` saves it on the user's Jellyfin as a client log (`POST /ClientLog/Document`, shown under Dashboard → Logs). TV: player Send log and Playback settings → Send device report; phone: player Info → Send log / Share and Settings → Send device report.
- Playback fixer: core `playback/PlaybackDoctor` turns a `PlaybackPlan` (server transcode reasons, `versions` with how each plays), the device caps and `PlaybackSettings` into plain findings with `PlaybackFix`es (another version/track, a `SettingsChange`, retry). In the player `PlaybackSession.diagnosis`/`applyFix` (re-asks the server from the same spot; a transcode stays forced only when Nitrate forced it after a failure); before playing `AppContainer.checkPlayback`/`applyPlaybackFix` (settings and versions only). TV: player "Why converting?" and details "How it plays"; phone: player Info → "Why converting?" and details "How it plays".
- Theme music: `MediaServer.themeSongs` (`Items/{id}/ThemeSongs`, inheriting the series') and `audioStreamUrl`; core-android `playback/ThemeMusic` (`AppContainer.themeMusic`) plays quietly with fades, keeps one song across details pages (series → season → episode), stops on leaving them, when a player opens and when the app goes to the background (each `MainActivity` onStart/onStop). `DisplayPrefs.themeMusic` (null = device default: on for TV, off for phones); each nav host's `DetailsRoute` show/hide it.
- TV quick profile switch: `NavEntry.onLongClick` (drawer, bar and dial all honour a held OK); "Switch user" long-press → `profiles/QuickSwitchDialog` (other profiles, PIN via `PinPad`, `AppContainer.switchAccount`, then Home).
- Library health (admins, Settings): `MediaServer.healthScan(libraryId)` reads movies and shows with artwork, `Overview`, `ProviderIds` and every file's streams (episodes per show), plus `isMissing` episodes; core `diagnostics/LibraryHealth.findings` sorts them into `HealthCheck`s (always converted on this device via `CapabilityRules`, duplicate copies by name + year, missing artwork, not identified, missing description, missing episodes) with `HealthFix`es; `AppContainer.checkLibraryHealth`/`applyHealthFix` (refresh missing metadata/images, `mergeVersions` = `Videos/MergeVersions`); Identify opens Manage, "How it plays"/Open the details page. Each app has a `LibraryHealthScreen`.
- Server speed check: `MediaServer.speedCheck` (JellyfinClient: `System/Ping`, `Users/Me`, `UserViews`, a recursive `Items` search, Home's row jobs each timed (`SpeedStep.parts`), `Playback/BitrateTest` 2 MB, and decoding the search answer locally), each step repeated and judged on its median; core `diagnostics/SpeedCheck` rates steps and turns them into findings (network / server / device). `AppContainer.speedCheck`/`sendSpeedReport` (client log). TV: Settings → Server speed check; phone: Settings → Server speed check.
- Search: screens show `MediaServer.searchHints` (`Search/Hints`, cheap) first, then `search` replaces it. Versions: `MediaItem.versions` from the item's media sources; `resolvePlayback` with no `mediaSourceId` picks the source this device direct-plays, then direct-streams, then the first; a choice on the details page lives in core-android `VersionChoices` (in memory) and `PlaybackSession` uses it. Multi-part titles (`partCount`) play on through `additionalParts` inside `PlaybackSession`. Details: `extras` (local trailers + special features) as an Extras row and a Trailer button (remote trailers open the URL), "More from <studio>/<year>" via `PersonRoute(studio=, year=)` and core `Browse.byStudio`/`byYear`. Players: chapter list (`chapterImageUrl`, core `playback/Chapters`), TV media next/previous jump chapters. There is no Upcoming row (removed: new episodes reach Next Up anyway). `MediaItem.isMissing` (virtual episodes) is never playable and labelled by core `AirDates.status`; whether seasons include them is the server account's `DisplayMissingEpisodes` (`showsMissingEpisodes`/`setShowMissingEpisodes`, round-tripping `Users/Me` Configuration). Browse filter choices come from `libraryFilters` (`Items/Filters`): genres, decades from real years, age ratings, tags.
- Every single-item "play" goes through `PluginRegistry.checkBeforePlay` (TV: `PlaybackGate`) so guards run; queued playback (playlists) deliberately bypasses it.
- Self-update: `core/update/Releases` reads the GitHub releases API (channel from the app id: `.dev` → dev pre-releases, `.debug` → none; version code from the `nitrate-version-code` marker in the notes, else `dev-N` → 1000+N; "What's new" = the notes' list items, written by `release.yml`). `core-android/update/AppUpdater` (`AppContainer.updater`) downloads, verifies against `SHA256SUMS` and installs through `PackageInstaller`; each app shows `UpdatePrompt`. Keep the asset names `nitrate-<mobile|tv>-<name>.apk`.
- Other Jellyfin clients (e.g. Wholphin, GPL) may inspire features, but never copy their code.
