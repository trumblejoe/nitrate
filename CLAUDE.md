# Nitrate

Jellyfin client for Android TV, Android phones/tablets, and (later) iOS. Kotlin (Multiplatform core), Compose, Media3, Ktor.

## Modules

- `:core` – Kotlin Multiplatform (jvm, iosArm64, iosSimulatorArm64). Nitrate's own models (`model/`), the `MediaServer` interface, the Jellyfin client (`jellyfin/`, Ktor + kotlinx.serialization), and all platform-neutral logic: rows, playback rules and test advisor, episode order, Fountain/.fadein, plugin logic. Code lives in `commonMain`; only the transfer server is in `jvmMain`. No `java.*`/`android.*` in `commonMain` — `./gradlew :core:compileKotlinIosArm64` catches it on Linux.
- `:app-core` – Kotlin Multiplatform (Android + iOS) app logic over `:core` shared by every app: `AppContainer` (built from an `AppPlatform`: DataStore files `AppStores`, HTTP engines, decoder probe, download scheduler, `ThemeMusic`/`NewEpisodeNotifier`/`AppUpdater` interfaces, network changes, timestamps), the stores (display, playback, session, plugins, profiles, search, backup; each takes its `DataStore`), `DataCache`/`LibraryCache` (`KeyValues`), view models, `SettingsSync`, `DeviceBackupManager`, `WritingStore`/`SharedWriting` (over `files/File`, okio), `RemoteControlHub` (`RemotePlayer`), `RowArtDrawing`. Packages keep their `dev.nitrate.android.*` names from before the move. `nowMs()` instead of `System.currentTimeMillis`.
- `:core-android` – Android side: `AndroidPlatform` (and `AppContainer(context, …)`), the DataStore files where Android always kept them (`AndroidStores`), OkHttp, `DeviceProbe`, `PlaybackSession` (Media3), `AndroidThemeMusic`, `AndroidNewEpisodeNotifier`, `AndroidUpdater`, WorkManager downloads, `PlaybackSession.report()`/`sendPlaybackReport(session)`.
- `:tv` – Android TV app (Compose for TV).
- `:mobile-ui` – the phone/tablet screens as a Compose Multiplatform library: every screen in `commonMain` (`MobileApp`, `LocalAppContainer`) except the player, which is per platform (`expect fun PlayerScreen`: Android's Media3 player and overlays in `androidMain`, Apple's player in `iosMain`). Platform needs go through `dev.nitrate.mobile.platform` (`Platform.kt` expect/actual: dates/numbers, `PlatformActions` copy/open URL/toast/volume, `PlatformBackHandler`, notification permission, image and file pickers, sound output, licence texts, artwork pixels, `ScriptTransfer`, `fullScreenDialog`, `windowSizeDp`); never call Android APIs from `commonMain` (`./gradlew :mobile-ui:compileKotlinIosArm64` catches it).
- `:mobile` – the Android phone/tablet app around `:mobile-ui`: activity, application, manifest, icons and the screenshot tests.
- `companion/` – Nitrate Companion, a Jellyfin server plugin (C#, .NET 10, against Jellyfin 12.4's NuGet packages; GPL-3.0 because it builds on Jellyfin's libraries) for what Jellyfin has no API for: chat in SyncPlay groups (`/Nitrate/Chat`, long polling), single sign-on (`/Nitrate/Sso`, open), household channels (`/Nitrate/Channels`), watch partners and private accounts (`/Nitrate/Partners`, `/Nitrate/Privacy`) and shared screenplays (`/Nitrate/Scripts`: owner + invited members, compare-and-set edits on the latest version, long-polled edits and cursors, kept in the server's data folder), spoken-line search (`/Nitrate/Lines`, `Lines/LineIndex`: SQLite FTS5 in `lines.db`, using the server's own Microsoft.Data.Sqlite, never shipped; filled by the "Index spoken lines" scheduled task, nightly and incremental, via `ISubtitleEncoder` as SRT) and the watch diary (`/Nitrate/Diary`, `Diary/DiaryHub`, one JSON file per user; `DiaryRecorder` hosted service records `PlaybackFinished` saves that ended played with no resume point). Apps find it with `GET /Nitrate/Companion` and hide features without it. Released as `nitrate-companion-<v>.zip` plus a plugin-repository manifest on the `companion-repo` release (`tools/companion-manifest.py`). Its plugin id is a storage key: never change it. Test with `dotnet test companion/Nitrate.Companion.Tests`.
- `:ios-app` + `iosApp/` – the iPhone/iPad app: `IosPlatform` (DataStore files in Documents, Darwin engines, `appleCapabilities` = `PlayerEngine.APPLE`: MP4/MOV direct play, fragmented-MP4 HLS, subtitles as WebVTT in HLS or burned in; `IosThemeMusic`; `IosNewEpisodeNotifier`: local notifications, checked in a `BGAppRefreshTask` (`AppDelegate` in `NitrateApp.swift`, `MainKt.checkNewEpisodes`) and after library changes, taps open the item via `IosApp.openItem`; no downloads or self-update yet) and `MainViewController` showing `MobileApp`, built into the static `NitrateKit` framework that the XcodeGen project `iosApp/project.yml` (Swift host `NitrateApp.swift`) links. The iOS player (`mobile-ui` iosMain `ApplePlayerSession`, `Player.ios.kt`) plays in Apple's player, or in mpv when the server would otherwise convert it for Apple's (`resolvePlayback(deviceCaps = Mpv.capabilities(...))`, `PlayerEngine.MPV`: every container, styled/image subtitles as they are; `MpvTracks` maps server stream indices to mpv aid/sid): mpv is MPVKit's LGPL product only (never MPVKit-GPL), driven from Swift (`iosApp/Nitrate/MpvPlayerView.swift`, `NitrateMpvPlayer`: Vulkan over MoltenVK, VideoToolbox) through ios-app `NitrateMpv`/`useMpv` (`close()`, not `release()`, which NSObject has) into mobile-ui `Mpv.factory`, with Nitrate's own controls (`MpvControls`). Both get the shared overlays (`PlayerOverlays.kt`: skip, Up Next, credits banner, `TrackPicker`); tracks via `trackSetup`/`pickTrack` (mpv switches in place for files played as they are). Linking needs macOS: `.github/workflows/ios.yml` builds an unsigned `nitrate-ios-<name>.ipa` for sideloading on pushes to `ios-app`, and `release.yml`'s `ios` job adds it (and its checksum) to every release; on Linux check with `./gradlew :ios-app:compileKotlinIosArm64`. Not on iOS yet: the player's chat, Info, More, still watching, second subtitles; downloads; the transfer page; licence texts.
- `:ass-renderer` – libass (ISC) with FreeType (FTL), HarfBuzz (MIT) and FriBidi (LGPL), built static by `tools/build-libass.sh` into `libassJNI.so` behind a small JNI bridge (`AssRenderer`); without that build it compiles with no native code and reports itself unavailable. core-android `playback/AssSubtitles` (`AssSubtitleView`, `PlayerView.assSubtitles()`) draws ASS/SSA in its own layer inside the player's content frame (video frames untouched); `PlaybackSession.assTrack` gives the whole script plus fonts (the file's attachments, or a download's `assFiles`/`fontFiles`), and Media3's own subtitle view gets nothing for that track. Keep `core/OpenSource` in step.
- `:dovi-converter` – libdovi (quietvoid/dovi_tool's `dolby_vision` crate, MIT; Rust) built static by `tools/build-libdovi.sh` (needs rustup) into `libdoviJNI.so` behind `RpuConverter.toProfile81` (one RPU NAL unit, profile 7 → 8.1); without that build it reports itself unavailable and profile 7 plays as its base layer. Keep `core/OpenSource` (libdovi and the shipped crates) in step.
- `:ffmpeg-decoder` – Media3's FFmpeg audio extension (Apache 2.0 sources; its video renderer is an upstream stub, left out) plus Nitrate's own software video decoder (`dev.nitrate.ffmpeg.FfmpegVideoDecoder`/`FfmpegVideoRenderer`, JNI in `ffmpeg_video_jni.cc`: H.264 incl. 10-bit, MPEG-2, MPEG-4 Part 2, VC-1; frames as 8-bit 4:2:0 drawn into the Surface as YV12; up to 1080p) over FFmpeg built LGPL with only those decoders (DTS, TrueHD, AC-3/E-AC-3, ALAC; ARM only) by `tools/build-ffmpeg.sh`. Without that build it compiles with no native code and reports itself unavailable. Players use audio via `EXTENSION_RENDERER_MODE_ON` and add the video renderer after MediaCodec's (both only when the device has no decoder); `DeviceProbe` counts them (`SOFTWARE_VIDEO_DECODER`, `VideoCodecCaps.softwareTenBit` for Hi10P over 8-bit hardware), and the profile keeps software video to 1080p and progressive (`VideoLimit.progressiveOnly`, `tenBitMaxHeight`), VC-1 MKV-only (`MATROSKA_ONLY_VIDEO`). Never enable GPL or non-free FFmpeg parts; keep `core/OpenSource` (the licences pages) in step with what ships.

## Commands

- Build: `./gradlew assembleDebug` (with DTS/TrueHD decoding: run `tools/build-ffmpeg.sh` first; needs the NDK named in `ffmpeg-decoder/build.gradle.kts`)
- Unit tests: `./gradlew test`
- If Maven Central returns 429, retry with `--max-workers=2`.

## Conventions

- Screens use `:core` models (`MediaItem`, `PlaybackPlan`…) and talk to the server only through `MediaServer`. Only `core/jellyfin` knows Jellyfin's API.
- Ids are strings (dashed lowercase UUIDs, as stored in settings and row keys) and times are milliseconds; conversion from Jellyfin's dashless ids and ticks happens in `core/jellyfin/Mappers.kt`.
- Jellyfin JSON is PascalCase (`JellyfinJson` maps camelCase DTO fields). DTOs are internal and hold only fields Nitrate reads. When calling a new endpoint, add it to `tools/trim-openapi.py`, regenerate `core/src/jvmTest/resources/jellyfin-openapi.json`, and exercise it in `JellyfinContractTest`, which checks paths, query parameters, body fields and enum values against the spec.
- TV: use `androidx.tv.material3` components so focus and D-pad behaviour are correct; every interactive element must be reachable and visibly focused with a D-pad. Text entry is `TvTextField`, which only opens the keyboard on OK and gives Up/Down back to the D-pad. TV player controls (`ui/player/PlayerControls.kt`): every button is a `PlayerButton` (alike until focused, then white and larger; play/pause round with its symbol); with the controls hidden, OK or an arrow only brings them back; Back closes the topmost thing (handled as a key by the player's root `onKeyEvent` → `goBack()`, as well as `BackHandler`: left to Compose, an unhandled Back first moves focus out of its group, which made More and Info take two presses; a More Settings page consumes Back itself to go back one step) (pop-up, side panel), then hides the controls (playing or paused), then leaves; closing a pop-up keeps the controls up and returns focus to the button that opened it (`ControlFocus`); sub-pages inside a pop-up go back one step; focus is never left nowhere: whatever had it going away (a banner, Up Next, a pop-up) hands it to `refocus()` (the controls' last button, else the player), a guard puts it back if it's lost with nothing open, and banners never take it from More, Info or a dialog (`CreditSceneBanner(takeFocus)`); Back closes what's open before a banner; buttons not yet usable still show focus (outlined, larger); Info is a panel over the video in place of the controls, sized to the screen and scrolled with ▲▼ (`PlaybackInfoPanel`); the remote's Menu key toggles the controls (and closes More or Info back to them); the More button (or Down from the buttons) opens More: `MoreSheet`, a panel across the bottom with the video above, tabs (◀▶; a tab shows when focused; opens on the tab used last) and one tab's `CardRow` or list below, built by `moreTabs`: the season's episodes (wrapping round, "Now" on the one playing, stills blur by `spoilerStill`, watched/progress marks per `DisplayPrefs`; OK plays through `onPlayNext`) or the films of the collection (`NextInCollection.saga`), Chapters (numbered placeholder without a picture), Cast (only with `DisplayPrefs.cast`; OK opens `PersonDialog` over the video: photo, role, born, biography scrolled with Up/Down, "Also in your library"), Extras (`MediaServer.extras`, the show's for an episode; OK plays on top via `onPlayExtra`, and Back/its end returns to the same spot through the entry's saved `resumeAt`; not in a SyncPlay group) and Settings (`PlayerChoicesTab` from `rememberPlayerChoices`: speed, sound, sleep timer, subtitle timing, audio sync, refresh rate (a per-playback `FrameRateMatch` for `FrameRateMatcher`, with `refreshNote` on how the video looks at the TV's rate now), each default from the device's own settings tagged DEFAULT; changes are for this playback, "Make default" saves them; Speakers, Second subtitles, Find subtitles and Watch together as pages that Back leaves: a page takes focus as it opens, and Back returns it to the chip that opened it, the list's `focusRestorer` held off meanwhile); not in easy mode.
- Images: both apps' Coil loader keeps a 512 MB disk cache; cards ask for small art (`backdropUrl(item, maxWidth)`), only full-screen views take 1920px, and the full-screen Home preloads the pictures one press away. Row pages prefetch into the disk cache (each app's `ImagePrefetch`): `PrefetchAlongRow` for the next cards in a row, `PrefetchRows` for the first cards of the rows below; prefetch the exact address the card uses (`rowCardImage(s)`), so a new row style or image size must update those too.
- Dependency versions live in `gradle/libs.versions.toml`.
- Rows (`core/rows/MediaRow`) have a stable `key` such as `home/next_up` or `library/<id>/recently_added`. Display settings are saved against it, so never rename a key.
- TV home and library pages both render through `ui/rows/RowsPage`; add row behaviour there, not per screen. TV Home is `FullArtPage` (one title full screen; ◀▶ items, ▲▼ rows) or `RowsPage`, chosen by `DisplayPrefs.tvHome`; every top-level page (Home, libraries, custom pages) wraps itself in `MainMenu(currentStopId)`, which shows `TvMenu` from the nav host's `LocalMenuCatalog` (libraries via `rememberLibraries` over core-android `LibraryCache`, which the phone's Libraries tab also uses) in the user's `DisplayPrefs.tvMenu` placement (left/right rail; Top/Bottom bar, at the top on the first row and the bottom on the last, as reported through `LocalMenuRows`; cardinal-only dial rings) with `tvMenuAutoHide` ("Fade in") for any of them and `tvMenuBlack` ("Black menu": rail, bar and dial on solid black) (the old `FADE` style reads as Top/Bottom + fade); reached by moving off the page's edge via `LocalMenuEdge` or the Menu key, never by taking over Back; focus leaving any page towards the menu is redirected to it (`TvMenu`'s page `focusProperties { exit }` → `toMenu`), so it always lands on a stop; with Fade in the menu always lays over the page (never a blank strip of its own). Library pages are laid out like Home unless `DisplayPrefs.tvLibraryLayout` says otherwise (full art with the tabs top right via `FullArtPage(header)`, the menu over it); switching tabs (and opening the page) keeps focus on the chosen tab; a library's tabs are core `pages/LibraryTabs` (`LibraryTab`/`LibraryTabKind`: Recommended, All, Genres, Collections, Unwatched, Studios, Decades and the user's own; `resolve` keeps the saved order and adds kinds it doesn't mention, `shown` always leaves one), saved per library with `DisplaySettingsStore.libraryTabs`, arranged in Settings → Display → Pages (`PageSetupScreen` lists Home and each library; both open the same frame, `SetupPage`: Theme first (`ThemeItem`, takes focus once, after it's built), then Tabs with the same `TabActions` (show/hide, rows, move, rename, remove) and "Add your own tab": `HomeSetupScreen` (Home always shows, its rows via `PageEditor`; then the user's custom pages, switch = pinned) and `LibraryTabsScreen`), never on the page; row tabs are `RowsViewModel` pages keyed by `LibraryTabs.pageKey` (Recommended keeps `PageKeys.library`), Genres/Studios/Decades rows from `LibraryTabs.rows` (`MediaServer.studios` = `Studios?parentId`), Unwatched is `BrowseLibrary(viewKey, startWith)`; Fast-forward/Rewind on a row (and in the Edit page's list and row menu, which also has an "Artwork style" line) step its `RowStyle` (`step`), named for a moment (focus waits on a holder in the row while its cards are swapped, then goes into the new style, and the whole row is brought back into view); the All view's A–Z bar goes where `DisplayPrefs.tvLetterBar` says (`LetterBarPlace`: Automatic = the side away from the rail, left, right, top, off). Its stops are `core/pages/MenuStops` ids arranged by the user (`tvMenuStops`, `tvDialStops` with `ring * 4 + spoke` slots; Settings always stays) in `MenuStopsScreen`, built into entries by `menuCatalog`; settings, tools and sign-out sit in `SettingsHubScreen`. Dialogs opened by a long press use `ignoreHeldSelect()` so the held OK button doesn't click their first option. TV art rows draw at a design size and shrink with `designScale` by `RowSize`. Poster, wide and showcase rows take `TV_CARD_SCALE`/`TV_BANNER_SCALE` of `RowSize`'s (phone-sized) heights (`tvPosterDp`/`tvWideDp`/`tvBannerDp`), pictures still asked for at full size so prefetch matches; the focused-title summary is 148 dp. `RowsPage` shows rows one at a time by default (`DisplayPrefs.tvRowsStacked` false, Display → Rows): the row in use sits along the bottom (`RowAtBottom`; the list has a screen's room above its rows so any row can; the row in use is placed again whenever it changes size, e.g. a showcase growing to the screen's height, which is given explicitly since the list's own height excludes that room; only the row's own request (`placeRow`) moves the page, a card's never does (art cards report their design size, which pulled the row up), so nothing jumps); showcase rows send ◀▶ off their ends straight to the menu (`LocalMenuEdge`); the tabs taking focus put the first row back in its place (`animateScrollToItem(0, roomAbove)`: the search for something above it could leave the list part-scrolled); no page has an Edit page button any more (`RowsPage(editButton)` defaults off; Settings → Display → Pages, or holding OK on a row); a row along the bottom keeps `RowFoot` under it and `CardRow` a few dp above and below its cards, so a focused card's growth stays on screen and the others are hidden until reached, so the backdrop and theme get the rest; no summary at the top: the focused title's `ArtCaption` (row and place as its label, logo off; `captionWidth`, narrow; `DisplayPrefs.tvCaptionSize` Normal/Compact = no description) sits in the corner `DisplayPrefs.tvCaptionCorner` gives (core `CaptionCorner.resolve`; Alternate = left/right row by row), rows' own titles off there (`LocalRowTitle`), with `ArtCaptionShade` on its edge; each one-at-a-time row is a screen-tall layer laying out caption and cards by `tvRowPlace` (core `RowPlace`: along the bottom/top, or down the left/right as `ColumnCards`: posters two abreast, other styles wide cards, ▲▼ along it, past its ends to other rows) and `tvRowExtent` (Full / Part way, `PartialShare`), the row starting beside the caption (so part way) whenever they share a line or side; Full art and showcases take the same corner and size; Left at a row's start goes straight to the menu (`LocalMenuEdge`, since the tabs could be "nearest" with the caption beside the row); an active showcase is scrolled past the room above so its top meets the list's; the tabs keep their place and fade; Left/Right never leave a row except towards the menu (the row's `focusProperties.exit`); coming back from the menu focus returns to the card left, not the tabs (`rows/FocusReturn`: `MainMenu` asks the page through `LocalFocusReturn`, `RowsPage` notes the last card and gives it the requester via `LocalReturnTarget`/`returnFocus(id)` on every card kind); library pages have no Edit page button (`RowsPage(editButton = false)`, Settings → Display → Pages does it); stacked, it keeps every row whole: moving into a row brings the entire row (title included) into view, and its vertical list uses `WholeRowInView` instead of the TV's pivot scrolling (art cards report their design size, which the rule tolerates); rows inside keep the TV behaviour. Page tabs (Home's pinned pages, a library's tabs and Albums/Artists) are `ui/components/PageTabs` in the user's `DisplayPrefs.tvTabStyle` (core `TabStyle`: chips, underline, sliding pill, large words, frosted glass, neon sign, cinema marquee, film strip, ink brush, ticket stubs; each keeps open and focused apart; picked in Display → Tabs via `TabStylePicker`, every style drawn live; tabs are always focusable and choose on OK's release). The page's tabs (`RowsPage(header)`) sit at the very top, above the focused-title summary, while on them or the first row, and slide away further down. The focused-title summary keeps a gap above the rows (2-line description); `FilmStripRow` is clipped to the page (never under the menu rail) and shows no caption of its own there (`caption = false`), since the summary already names the focused title.
- Custom pages pinned to Home are Home's tabs on TV ("Home" then each pinned page, the same tab strip as library pages: top right on full art via `FullArtPage(header)`, which leaves keys to the tabs while they have focus; `HomeScreen` `PinnedPage`, focus kept on the chosen tab through the page's redraws), not menu stops by default. Pages (Home `PageKeys.HOME`, library overviews `PageKeys.library(id)`, custom pages `PageKeys.custom(id)`) are assembled by `RowsViewModel` from built-in rows plus the user's `PageLayout` (core `pages/`): order, hidden, renamed and custom rows (`RowSource` query/collection/playlist). Layouts, custom pages and `DisplayPrefs` live in `DisplaySettingsStore` (in the device's display profile, see below) and sync like other display settings. Spoiler hiding: `isSpoiler` blurs unwatched episodes' stills; `hidesDescription` holds back descriptions of unwatched episodes and movies (details pages offer "Show"). Anything shown about an item (ratings, overview, badges, titles, progress...) must respect `DisplayPrefs` via each app's `LocalDisplayPrefs`; use `DisplayPrefs.facts(item)` for fact lines.
- Metadata locks and bulk editing (admins): field locks are core `admin/LockableField` (Jellyfin's `MetadataField` names only; `saveMetadata` drops anything else, since an unknown name makes the server refuse the save), toggled by the lock icons/chips in each app's Manage → Details. `admin/BulkEdit` (add/remove genres, tags, studios; set/clear age rating; lock/unlock fields or the whole item) reads, changes and saves each title's own metadata (`run` reports changed/unchanged/failed); each app's library "All" view has an admin "Select to edit" mode → edit, review (`describe`), apply, results (`BrowseViewModel.reload` after). Manage → Details also shows the title's theme music (`MediaServer.themeMusicInfo`: own or the series', with a preview).
- Admin calls live in `core/jellyfin/JellyfinAdmin.kt`. Item updates and user policies round-trip the server's own JSON (never rebuild them from DTOs) and drop read-only parts first (`READ_ONLY_ITEM_FIELDS`; 12.4 can't parse its own `Trickplay` back). Admin UI shows only when `AppContainer.account` says `isAdmin`.
- Shared test fixtures (`FakeServer`, sample art) live in `testing/` and are on both apps' test source paths.
- Direct play first, then the device's hardware decoder, its own software decoder, Nitrate's FFmpeg; the server converts only what none of those can do. `PlaybackSettings.maxBitrate` defaults to `NO_LIMIT` (1 Gbps; Jellyfin takes an Int): a file is never converted for its bitrate alone (a slow network buffers instead); "No limit" is the first `BITRATES` choice. Learned failures are narrow: a title that fails as it is (`recordFailure(..., itemId)`) is converted from then on (`failedTitles`, `convertsTitle`, forced in `PlaybackSession.start`; PlaybackDoctor offers `ForgetTitle`), a whole codec/HDR type only once `LearnedFailure.BLOCK_TITLES` (3) different titles failed (`blocksFormat`; older count-only records need a count of 3), and both are let go after `KEEP_MS` (60 days, `forgetOldFailures`). The profile converts up front only profiles no decoder here takes (`VideoCodecCaps.missingProfiles`, from `DeviceProbe.CHECKED_PROFILES`: H.264 4:2:2/4:4:4, HEVC Range Extensions, which Android can't even claim), except that H.264's go to Nitrate's FFmpeg up to 1080p progressive when it's built (`softwareProfiles`; Media3 picks it when MediaCodec turns the profile down); "Always" for a codec lifts this. Media3 direct plays AVI, MPEG program streams (.mpg/.vob) and FLV too (`DIRECT_PLAY_CONTAINERS`; the DV profile 7 extractors factory wraps Media3's defaults).
- Playback capability ids are a codec name (`hevc`, `eac3`) or `range:<HDR format>`. Playback settings are per device and must never be synced; display settings are per user and sync through `SettingsSync`. Track choices (`TrackMemoryStore`, keyed by core `TrackSelection.memoryKey`: the show for an episode, the title itself for a movie, kept for good) are display settings and sync, and hold only the kind of track the user picked (audio or subtitles, language plus the track's title so "Commentary"/"Signs" is found again; `TrackMemory.VERSION`) so the rest follows the server account's language settings, which Jellyfin applies through PlaybackInfo's default stream indices. What starts is `TrackSelection.initial`: pick → server's picks → file flags; playback reports carry the audio and subtitle stream indices (sent again at once after a track change), so the dashboard shows them and, with the account's Remember selections on, the server keeps the last pick per title (by index; not across episodes, which is what Nitrate's own memory adds); picks can be made in the player, on details pages (phone `TrackLine`, TV `TrackButtons`, via `AppContainer.trackSetup`/`pickTrack`; How it plays uses them) and in the download dialog (`TrackRequest`; a smaller copy keeps only the picked audio; "Burn-In Subtitles" has the server draw the picked subtitle into a converted download, `DownloadRecord.burnedSubtitle`, listed with delivery ENCODE); night mode, subtitle style, PiP and background audio are playback settings.
- Display profiles (core `pages/DisplayProfiles`): display settings live in profiles; each device's choice of profile is device-only (`DisplaySettingsStore.useProfile`, stored outside the synced map). Profile entries are stored as `p:<profile>:<name>`; shared on every device (`DisplayProfiles.isShared`): custom pages and their layouts (`layout:custom/...`), per-series languages (`tracks`), the profile list and `shared` (spoiler hiding, read over `DisplayPrefs.hideSpoilers`). Built-in profiles TV/Phone/Tablet (`DeviceKind`, chosen by `AppContainer.deviceKind`) are never written: choosing one asks for a name and creates a profile; a change made while on one forks a profile named after the device. Settings saved before profiles migrate to "My settings" (`migrated`). `SettingsSync` keeps everything under display-preferences id `nitrate-display` (older versions still write the single set under `nitrate`, only read once to seed) and merges per entry against the last agreed copy (`DisplayProfiles.merge`) so devices never undo each other. TV: Settings → Display profile, including importing only another profile's radial menu (differences first).
- Settings layout (same groups on both apps): the settings themselves (Picture & sound with an Advanced page for tunneling, DV profile 7, 3D, resolution limit, learned failures, direct play/stream and the format lists; Subtitles; Display with a "What's shown" page; While watching), then Account & servers, Your watching, Tools (tests, speed check, device report, admin pages), About (updates, plugins, licences). TV: `SettingsHubScreen(SettingsSection…)`, `PlaybackSettingsScreen(page = PlaybackPage…)`, `DisplaySettingsScreen(page = DisplayPage…)`; phone: the Settings tab links to `SettingsPageRoute(SettingsPage…)` (`SettingsPageScreen`). Every page or group says where it applies with core `settings/SettingScope` (this device only / display profile, `DisplaySettingsStore.activeProfileName` / all your devices) via each app's `ScopeTag`. Everyday choices stay on the main pages with a one-line "when to use it"; anything only for troubleshooting goes under Advanced.
- Device backups: each device's own settings (playback + plugins, `core/backup/DeviceSettings`; never PINs/profile choices, scripts have their own backup) are saved by core-android `backup/DeviceBackupManager` (`AppContainer.backups`) to the user's Jellyfin display preferences (`nitrate-device-<deviceId>`, listed in `nitrate-devices`; each device writes only its own) a few seconds after any change, but only once the account is "settled": after first sign-in a device with other backups asks "Set this device up like…" (`offer`, each app's `BackupPrompt`) and nothing is pushed until it's answered ("Not now" keeps a reinstalled device's old backup as "(earlier)"). Restores always show `DeviceBackups.differences` first and apply only on confirm; hardware results (overrides, learned failures, height limits, 8/10-bit) carry over only from the same model (`DeviceBackups.restored`). Settings → Device backup on both apps; the phone also exports/imports a file.
- Remote control: `AppContainer.remote` (`RemoteControlHub`) listens to `MediaServer.events()` and forwards commands to the player that registered itself as `remote.active`; each app handles `Play`/`DisplayMessage`/volume itself (TV `PlayerRoute.audioIndex`/`subtitleIndex` carry a Play's tracks into `PlaybackSession.load`). The phone is the remote: `MediaServer.controllableSessions` (the user's own, `controllableByUserId`) through core `remote/RemoteDevices` (other devices, playing then Nitrate first, newest session per device); "Play on…" (`PlayOnDialog`, details page and player More) sends `playOn` with the tracks Play would start with and opens `RemoteScreen` (seek, keys, volume, Audio/Subtitles via `setSessionTrack` = `Sessions/{id}/Command`); `PlayingElsewhereBar` above the nav pill while one of them plays.

- Refresh rate (TV): `PlaybackSettings.frameRateMatch` (Off / Only when seamless / Always), per device; `FrameRateMatcher` switches modes via core `DisplayModes.best`: an exact whole multiple at the same resolution first (23.976 → 23.976 Hz before 47.952/119.88), else a near one within `DisplayModes.NEAR` (24 Hz for 23.976) rather than leave 3:2 judder, never away from a mode that already nearly fits; `DisplayModes.cadence` says EXACT/NEAR/JUDDER. The TV's black while it re-syncs can't be shortened, so the matcher switches before the video starts (the server's stream frame rate, then the file's), holds playback behind `MatchingRefreshRate` until the mode changed plus `SETTLE_MS`, keeps the rate across players for `KEEP_MS` (`ModeHold`: next episode or extra, one switch), resets at once only when the choice stops being Always (`match` is null until settings load, so a default never hands a kept rate back), and logs what it saw and did. A switch drops the HDMI link for a moment (the output takes only PCM meanwhile), so sound set up then was decoded and stayed so: the track selector re-chooses on capability changes (`setAllowInvalidateSelectionsOnRendererCapabilitiesChange`), and after the settle the matcher calls `PlaybackSession.recheckAudioOutput()`, which rebuilds the audio (audio track type off and on) when surround the output takes again was decoded for no reason of Nitrate's own. The switch is made before the player sets up sound at all: `PlaybackSession.beforePlay` (set by `FrameRateMatcher`) runs once the server answered and before `play`, switching to the stream's rate; after the settle the matcher waits for surround passthrough to come back (`awaitPassthrough`, for as long as this TV's device check measured, else 4 s) before rechecking.
